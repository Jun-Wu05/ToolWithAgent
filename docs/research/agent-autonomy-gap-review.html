01TL;DR

现状定位

按 Anthropic《Building Effective Agents》分类，这是教科书级的 workflow（固定编排），不是 agent：LLM 只在一次规划调用产出静态 PlanDecision（planner.py:45 tools=[]），之后控制流全在 Python for 循环（execution.py:162）。这是有意识的工程立场（ADR-0005 失败关闭），不是落后。

「不智能」的两个根因

失败点奇怪：正则守卫在中文表层模式开火（10 个填充动词表、短语正则、字段白名单），且失败零重试。回答机械：追问是 message_code 模板；Planner 只见 SessionFacts 目录不见值，无米下锅说人话。

能否变自主：能，不必推翻现有架构

演进缝已被 ADR-0010 威胁链验证（执行结果 → 构造新计划 → 再走 PlanExecutor）。推荐渐进式半自主（L1→L2→评估门禁后选择性 L3），每阶段用评估门禁决定是否继续放开。

首选切片（已确认）

失败自恢复层 RecoveryOrchestrator + 执行反馈回喂 + 追问生成化：把「失败即停问人」变成「有界自恢复 ≤N 次，穷尽预算或不可逆操作才问人，且问得有人话味」。预算设 0 即回到现状，演进完全可逆。

04根因解剖：「失败的点很奇怪 · 回答很机械」

为什么失败点奇怪

  • 失败发生在表层模式匹配而非语义理解：10 个填充动词表（planner.py:86-108）——换个说法如「设置到」就绕过或误触发
  • 字段白名单守卫（execution_policy.py:127-158）只有两个出口：硬跑失败或问人——没有第三个出口「agent 先自查再决定」
  • 计划级预拦截（execution.py:142, #148）让用户看到「计划被拒」而非「哪一步可以修」
  • Planner 零重试（不变量）——网络抖动也变成一次追问
  • 本质：每条守卫都是某个线上 bug 的创可贴，累积后失败位置由正则覆盖面决定，与用户语义无关

为什么回答机械

  • 追问文案是 message_code 模板渲染（plan_renderer.py:100-103），不携带会话上下文
  • Planner 只见目录不见值（session_facts.py:18-42；ADR-0006 仅 2 个产物槽位）——不是不会说人话，是没有素材
  • 历史窗口仅 6 条 × 2000 字符（planner.py:52-57），多轮来龙去脉被截断
  • 13 种产物名映射硬编码（plan_renderer.py:49-68）

07候选改造卡片（8 张）

① 失败自恢复层 RecoveryOrchestrator

Strong
application/execution.py · 新增 application/recovery.py

问题：needs_input/failed 一律立即交还人类；多数失败原因（字段名差一个字、依赖顺序错）在会话事实里就有答案，只是没人去看。

方案（拷问定稿，ADR-0011）：失败时先有界自恢复（每计划 ≤2 次）：决策器只见类型化失败步骤 + error_code + facts，不见用户原文；输出受限修订枚举而非自由计划。合法动作仅三类：①瞬时重试 ②结构修正（均为确定性）③系统推导参数重推导（唯一 LLM，≤1 次）。用户点名参数一律不碰；会覆盖用户手动产物 → 直接升级追问。

for step in plan.steps: result = adapter.execute(step, ctx, deps) if result.status != SUCCESS: break # 失败即停→模板追问 if result.status != SUCCESS: revision = orchestrator.decide( # 不见原文；①②确定性，③才调LLM failed_step, error_code, facts, budget) if revision is ESCALATE: break # 超出动作集/不可逆/预算尽 plan = apply(plan, revision) # 仍是类型化计划，照过 policy continue outer_loop

收益：一个接缝覆盖 12 类步骤失败恢复；policy 校验资产全复用。不违反 ADR-0005（初始规划仍一次成型）→ 已定稿 ADR-0011。

② ExecutionReport 回喂通道

Strong
contracts/session_facts.py · application/execution.py

问题：执行账本生成后只用于渲染，规划侧永远看不到「刚才发生了什么」。

方案：账本受控摘要（每步 status/error_code/产出计数）扩入 SessionFacts 新字段 recent_execution；守卫保持「值不外泄」，只暴露目录与状态。

Before

After

09首选推荐

先做 Phase 0（清理，零风险）+ Phase 1（失败自恢复 + 回喂 + 追问生成化）

  • 直击已确认的最痛体感（失败点奇怪 + 回答机械）
  • 全部候选中杠杆/风险比最高：一个接缝覆盖 12 类步骤的失败处理，复用全部现有确定性资产（policy 校验、类型化计划、原子写回、审计账本）
  • ADR-0010 威胁链已验证这条缝——Phase 1 是把特例泛化为机制
  • 不动初始规划不变量（ADR-0005 保持成立）；预算设 0 即回到现状，演进完全可逆
