# ADR-0011: 有界自恢复循环

日期：2026-09-10
状态：已接受（agent-autonomy-evolution PRD 拷问定稿，grill-with-docs 拷问结论）

## 背景

步骤失败或缺参时系统一律立即交还用户（needs_input / failed → 模板追问），用户体感「失败的点很奇怪、回答很机械」：失败位置由正则守卫覆盖面决定而非用户语义决定，追问文案是 message_code 模板。ADR-0010 已在威胁链上验证「执行后构造新计划 → 再走 PlanExecutor」的接缝；本决策把该特例泛化为通用机制。

## 决策

在 application 请求运行时层新增 **RecoveryOrchestrator**：PlanExecutor 产生失败结果后、升级追问之前，于**合法动作集**内尝试自恢复并续跑。术语与边界见 CONTEXT.md「自恢复」条目，要点：

- **合法动作集仅三类**：① 瞬时失败重试（步骤级超时、限流、5xx、模型输出结构解析失败 → 同参数原样重跑；Planner 自身失败不在内）；② 计划结构修正（重排、拆分、依赖补齐，不改任何参数值）；③ 系统推导参数重推导（威胁类型链路来源字段、日志格式识别等系统自判值，结果不合理时换策略重选）。
- **不修改用户显式点名参数**（含大小写差异；#122 例外不因此扩大）；**不接触用户原文**；输出为**受限修订枚举**（retry_as_is / restructure / rederive_system_param / escalate），不是自由 PlanDecision——在结构上排除重新理解意图的可能（#15 反模式）。
- **①② 纯确定性策略判定，仅 ③ 允许调用一次 LLM**（上界）。首版（#225）③ 以确定性启发式实现——「结果不合理」= 提取值落「其他」占比 ≥ 阈值，「换哪个」= 威胁链 S1 候选得分表下一覆盖候选——LLM 调用 0 次；仅当 #227 门禁数据证明启发式不足时再引入 LLM 判断。
- **预算按计划计**：每计划自恢复合计 ≤2 次、③ ≤1 次、同步骤 ① ≤1 次；预算可配，设 0 = 完全回到现状行为；会话级只计数不限制（供评估与告警）。
- **不可逆判据 = 会覆盖或删除用户手动产物**（手动字段调整、规则数据源字段、枚举映射附件贡献、手工改过的事件名称）→ 不进入自恢复，直接升级追问。导出、日志知识申请、删除字段本身不因此归为不可逆（幂等或需审批）。
- 升级追问的文案经 **ClarificationComposer** 生成：与 Planner 同视野（只见 SessionFacts，不见任何业务值），choices 仍由确定性代码供给，生成文案过渲染校验。
- SessionFacts 新增**最近执行摘要**（recent_execution）：当前计划 + 上一份已完成计划的步骤级摘要（step_id / type / status / error_code / 产物目录与计数，不含值）；新计划开始时滚动，主数据替换时清空。

## 排除的替代方案

- **允许语义改参（相似度最高字段直接替换）**：推翻「不代用户改参」领域原则；恢复决策器一旦可见用户原文就会重新理解意图，是 #15 反模式再现。
- **Planner 失败重试**：破坏 ADR-0005 一次 Planner 不变量。
- **全面 agent loop（L3）**：无评估基线佐证前不放开；多提供商接入不满足「less structure」的前沿模型前提，错误复合风险高（见 PRD Phase 4 门禁）。

## 关键语义

- 恢复修订后的计划照走 `DefaultExecutionPolicy.validate_plan / validate_step` 与 PlanExecutor——现有确定性资产（类型化计划、白名单、原子写回、审计账本）全复用。
- 每次自恢复与升级追问计入审计：恢复类型、触发 error_code、修订内容、结果状态；独立 logger 与指标计数（会话级）。
- ADR-0010 威胁链保持现状行为不变，成为最近执行摘要机制的首个消费场景。

## 影响

- 每计划新增最多 1 次 LLM 调用（③）+ 0-2 次确定性重执行。
- ADR-0005 不变（初始规划仍恰好一次）；ADR-0006 延伸（产物槽位之外新增执行摘要）；application-runtime-extraction 的调用冻结不受影响（新增调用点不属于其冻结的既有阶段）。
- 实施于 agent-autonomy-evolution PRD Phase 1。
