# ADR-0007：提供商注册表

- 状态：已接受
- 日期：2026-08-24
- 关联：CONTEXT.md「模型提供商」术语；多提供商接入 PRD

## 背景

多提供商支持此前按 if/else 分支实现，散落在六个消费点：模型构造（ModelConfig._build_model）、日志解析直连链路（llm_client 的 URL/key/能力判断）、模型列表与连接测试（model_manager）、设置界面供应商下拉框（settings_handler 与 start_handler 三处硬编码 values）。每次新增一家提供商需要同步修改六处，且已产生三类一致性缺陷：

1. 直连链路用 import 时类属性快照判断提供商，运行时切换后 response_format 判断不随切换生效；直连 URL 与 key 一旦懒加载缓存即不再更新。
2. 密钥缺失行为不一致：Team 构造对 DeepSeek 抛错、对硅基流动仅告警；UI 保存只对 DeepSeek 校验。
3. 启动策略与 .env 优先语义冲突：Team 仅在 UI 保存设置后创建（get_team_instance 唯一调用点在 settings_handler），.env 配置完整的用户不碰设置界面则所有消息被「Team未初始化」拒绝，与 ModelConfig「运行时覆盖 > 环境变量」的设计意图矛盾。

## 决策

引入**提供商注册表**：每家提供商的全部接入参数收敛为单点声明的 ProviderSpec 条目——模型构造方式（agno 类与参数）、密钥环境变量名、直连 chat/completions 端点、JSON 结构化输出能力（response_format）、模型列表端点与静态默认表、连接测试参数。六个消费点全部改为查表，不感知具体提供商。

- **接入完整性**：一家提供商只有在 Agent 模型构造、直连调用、设置界面三条链路全部打通时才算接入；新增一家 = 新增一条规格，消费点零改动。
- **密钥统一口径**：聊天密钥按当前家环境变量解析、FALLBACK_API_KEY 兜底；各提供商缺失行为一致（构造时抛出带具体变量名的错误，UI 保存时按最终解析结果校验）。嵌入向量密钥独立固定硅基流动，与聊天提供商无关。
- **.env 优先**：Team 懒初始化——环境变量配置完整即可直接使用，设置界面是可选的会话级覆盖，不是必经之路。
- **能力声明可修订**：能力认知更新（如智谱已官方支持 response_format）只改一条声明，不改代码。
- **思考模式禁用列表**保持全局模型级单点定义（思考是模型特性，与托管提供商无关）；超时/重试参数不进注册表（无真实按家差异需求，保持统一值与调用方传参现状）。

## 公共不变量

- 注册表是提供商接入参数的唯一事实来源；任何消费点不得再出现 per-provider if/else 分支或硬编码端点。
- 消费点通过注册表公开查询接口取值，不感知条目内部结构。
- 密钥解析优先级不变：运行时会话配置 > 当前家环境变量 > FALLBACK_API_KEY。

## 取舍

声明式注册表要求一次性重写六个消费点（迁移成本高于逐家加分支）；换取的是新增提供商边际成本降为一条声明、能力与端点认知集中可审计、并消除三类已发现的一致性缺陷。若沿用分支式扩展，五家 × 六处的分支矩阵将不可维护。首版不按模型粒度声明能力（如智谱部分模型不支持结构化输出），依靠默认模型表只收录已验证模型 + 连接测试暴露异常来兜底。
