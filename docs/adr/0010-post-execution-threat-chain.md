# ADR-0010: 威胁类型链路的执行后确定性续跑

日期：2026-09-02
状态：已接受（issue #173 定稿，grill-with-docs 拷问结论）

## 背景

字段映射的事件名称标注发生在**执行中**（映射成功后才知道哪些子规则是威胁组）。
「判定出威胁子规则后自动补全威胁类型链路」需要一个在标注结果可用之后产生并执行
新计划的机制。

## 决策

在 **application 请求运行时层**（`request_runtime.py`）做执行后钩子：主计划执行
返回 `ExecutionReport` 后，`application/threat_chain.py` 检查报告中的字段映射产物
标注（S0 触发判定），满足条件时构造确定性四步计划（enum_extract → threat_mapping
→ [delete_fields] → add_fields → fill，纯函数构造于 `threat_chain_policy.py`），
经统一 `PlanExecutor` 在会话配置副本上续跑（S2-S5）。整条链成功后才
一次性提交 `mapped_sub_rules` 与链路产物，然后将汇总追加回主报告（S6）。

新计划产生源由此增加为三类：Planner 规划、Web 确定性按钮、**执行后确定性续跑**。

## 排除的替代方案

- **Planner 预生成四步**：标注在执行中才发生，规划期无法知道威胁判定与来源字段 X，
  违反 planner.md「计划不得依赖执行期才产生的状态」精神。
- **适配器内部串行执行**：FieldMappingAdapter 返回单步 StepResult 的契约会被破坏，
  且适配器内构造第二份计划引入循环导入与职责混淆（映射适配器不应拥有链路编排权）。

## 关键语义

- 失败隔离：链路任何失败/异常都不降级主报告状态，仅追加成功步骤行与 🔗/⚠️ 汇总行；配置副本不提交，会话保留替换前有效配置。
- 整体替换：换源时只清理目标威胁子规则中链路自产的「威胁类型」 normalize 及全部同名 addFields 键，保留原始来源字段、非威胁子规则和其他 addFields 键；新生成条目固定为 `field=threat_type`、`entity=威胁`、`sim=true`、`core=false`。
- 会话级来源覆盖（#129 临时字段模式）：显式指令链路成功后记录，自动入口优先使用，
  新上传主数据/重新日志类型提取时清除。
- 威胁映射产物填充目标固定为「威胁类型」（修复跨轮血缘漂移）。
- 可观测性：专用 `threat_chain` logger，S0-S6 六阶段一行结论 + DEBUG 决策明细
 （S1 全量候选得分表），挂既有 TraceContext span 树。

## 影响

- 字段映射轮新增最多 2 次 LLM 调用 + 1 次候选检索（进度经类型化步骤机制渲染）。
- 「威胁类型」成为第 4 个映射目标黑名单字段（#125 先例）。
- 复合指令「提取枚举+映射到威胁类型」从 2 步变 4 步（breaking，需求本身）。
