# ADR-0002：快路径/慢路径路由策略（RouterAgent 在明确意图时被绕过）

**日期**：2026-07-16
**状态**：已采纳（待增强）

## 背景

系统使用 `detect_intent`（关键词 + 状态 + 消歧规则）判断用户意图。意图明确时直调 MemberAgent（跳过 RouterAgent），省 1 次 LLM 调用。意图模糊时走 RouterAgent。

## 决策

采用**快路径/慢路径分流**：

- **快路径**（明确意图）：关键词匹配 + 状态前置检查 → 直调 MemberAgent → 1 次 LLM 调用
- **慢路径**（模糊/复杂意图）：交 RouterAgent 思考 → 引导用户或分解执行 → 2+ 次 LLM 调用

## 理由

1. **性能**：明确意图（占多数）跳过 RouterAgent 省 1 次 LLM 调用（~5-10 秒 + token 消耗）
2. **Agent 的真正价值在引导和分解**：RouterAgent 被绕过不是问题——它的职责不是重复关键词能做的事，而是在意图不清时**引导用户**（"你有数据吗？请先上传"）或在复合需求时**分解执行**（"先提取枚举值，再威胁类型映射"）
3. **快路径的 status 前置检查兜底**：mapping 意图但无数据 → 改为 general（交 RouterAgent 引导），避免直调报错

## 已知限制（待 PRD 增强）

当前 RouterAgent 的引导和分解能力**尚未充分实现**：
- 复合意图（"提取A的枚举值再威胁映射"）不会被分解为多步操作
- 意图引导（"字段映射"无数据时主动引导上传）依赖 detect_intent 的 general 降级，而非 RouterAgent 的主动思考

这些是后续 PRD 需要定义的增强方向。

## 后果

- **正面**：明确意图秒级响应，省 token；RouterAgent 保留给真正需要思考的场景
- **负面**：RouterAgent 当前能力有限，复杂/复合意图处理需要增强
- **不变**：快路径直调策略保留，不因 RouterAgent 增强而移除
