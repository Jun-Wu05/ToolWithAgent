# ADR-0012: SQLite 作为日志解析知识的单一事实源

日期：2026-09-17
状态：已接受（#202）

## 背景

旧日志模式存储同时依赖 SQLite 元数据、NumPy 向量文件和 JSON sidecar。三者无共同事务，缺失或失配时无法判定真实状态；旧记录也没有审核状态和竞争配方的原子替代约束。

## 决策

- SQLite 是日志解析知识的唯一运行时事实源。默认路径为 `config/log_patterns.db`，只允许 `LOG_KNOWLEDGE_DB_PATH` 或测试显式注入覆盖。该本地数据库不提供跨实例同步。
- 日志知识申请只有“待审核”“已批准”“已拒绝”三种状态。普通候选投影只返回已批准配方，不返回原始日志样例。
- 每份申请按 SHA-256 去重并最多保留 10 条样例。只有已拒绝申请可删除，删除时级联清理样例。
- 同日志结构、同选择模式及同显式分类特征字段范围最多一份已批准知识。批准竞争申请必须在一个事务中拒绝旧记录、记录双向替代关系并批准新记录。
- 旧 SQLite 表在 schema 初始化事务中幂等迁移。能用已保留样例重建和回放的记录进入待审核；无效元数据、提取器或回放失败的记录进入已拒绝。任何旧记录都不自动批准。
- 移除日志知识运行时对 NumPy、字段检索 embedding 和 JSON sidecar 的依赖。JSON、KV 与 Header 正常分类路径不调用知识仓储，仅返回本次分类结果；待审核申请由后续的用户显式提交入口创建。

## 排除的替代方案

- **保留 SQLite + NumPy + JSON 三份状态**：无法原子更新，启动时难以判定哪份状态权威。
- **迁移时自动批准旧配方**：跳过管理审核，且旧数据没有足够证据支持公共复用。
- **在本切片实现候选排序或确定性回放**：这些属于后续运行时集成，会混淆仓储约束与匹配策略。

## 影响

- 标准字段候选检索的 embedding 缓存与客户端保持不变；本决策只移除日志解析知识的向量依赖。
- 原始日志仅存在审核详情边界；普通候选投影、运行日志与稳定异常不包含原文。
- 用户显式提交、管理审核界面、候选排序、确定性回放和日志分类命中接入仍属后续 issue。
