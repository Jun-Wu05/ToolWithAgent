# ADR-0013：Chainlit 与 V2 旁路并行入口

- 状态：已接受
- 日期：2026-09-18
- 关联：ADR-0009、ADR-0011；ToolWithAgent V2 PRD（编写中）

## 背景

现有 Chainlit 入口仍承担实际业务处理。V2 需要引入 React/FastAPI、持久化任务、后台 Worker 和运行追踪，但开发和上线不能要求现有用户暂停使用，也不能让 V2 的故障、依赖或未完成数据模型破坏 Chainlit。

ADR-0009 已把业务运行时从 Chainlit Web 中提取到 UI 无关的 `application/`，因此两个入口可以复用同一业务实现，不需要复制字段映射、枚举填充和规则导出逻辑。

## 决策

采用旁路并行入口，而不是原地改造或让 Chainlit 先接入 V2 基础设施。

- Chainlit 保持现有地址、启动命令、依赖环境、会话状态和业务路径。
- V2 使用独立地址与端口、Python 环境、React 依赖、SQLite、上传/产物目录和后台 Worker。
- 两个入口只共享 Application 业务源码和只读的平台标准字段表；标准字段表不是 V2 改造对象。
- V2 的持久化与任务机制包装在 Application 调用边界外。Chainlit 不依赖 V2 数据库或 Worker。
- 初期不迁移、不读取且不双写 Chainlit 会话、任务和历史结果；V2 任务中心只展示 V2 数据。
- 现有业务 Prompt 不因界面和运行载体迁移而修改。V2 新能力如确需 Prompt，新增独立用途文件。
- 共享业务代码只能做默认保持现有行为的向后兼容扩展；合入前必须通过完整测试和 Chainlit 业务验收。
- 涉及共享业务代码的发布必须使用同一组脱敏真实样本进行双入口兼容验收；至少覆盖字段映射、枚举填充、手动调整、威胁类型再次校验、模型失败恢复、导出命名与平台导入。
- V2 复用现有导出文件命名逻辑，保持名称前缀、扩展名和时间格式。
- 开发环境默认一个 V2 Worker、模型任务并发数为一；并发数可配置，不作为正式版本硬限制。
- V2 上线后仍保留 Chainlit 作为独立回退入口；下线时机另行决策。

允许的关系为：

```text
Chainlit Web ─┐
              ├─→ Application → Adapters / Domain
V2 API/Worker ┘

Chainlit 会话存储  ╳  V2 持久化存储
```

## 后果

### 正面

- V2 可以按垂直切片持续开发和合入，而不改变现有用户入口。
- V2 安装、启动、队列或存储失败不会阻断 Chainlit。
- 两个入口复用同一业务核心，避免维护两套字段映射与规则生成实现。
- V2 出现严重问题时可直接恢复使用 Chainlit 处理新业务。

### 负面

- 两个入口的会话和历史结果互不可见，用户回退后需要重新上传输入。
- 开发和过渡期需要维护两套启动与部署说明。
- 共享 Application 的改动仍可能影响两边，因此完整回归和 Chainlit 验收是强制门槛。

## 不采用的方案

- **原地把 Chainlit 改成 V2 客户端**：过早让现有入口依赖未稳定的数据库、队列和 API。
- **Chainlit 与 V2 双写**：增加一致性失败和修复成本，并直接触碰当前稳定路径。
- **复制业务实现**：短期隔离但会迅速产生两套不一致的规则语义。
- **V2 上线即删除 Chainlit**：失去低成本回退能力，且没有实际运行观察依据。
