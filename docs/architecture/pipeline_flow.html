📊 日志解析 Pipeline 数据流 (v3)

Step 1 Format Identifier — 格式识别

负责模块：log_format_identifier.py

输入：原始日志字符串

LLM 调用：✅ 调用 LLM 分析格式

输出关键字段：

字段说明示例
format格式类型JSON / unknown
format_detail格式描述纯JSON / 日志头+JSON
has_header是否有 syslog 头true / false
feature_field分类字段名（初步建议）categoryName
header_end_marker头与 body 分隔标记" - - - - "
↓

Step 2 Classifier — 特征分类（路由入口）

负责模块：log_classifier.py — _do_classify_log_features()

路由规则：

条件路径说明
format != jsonUNSUPPORTED非 JSON 暂不支持
"日志头" in format_detail→ Step 2a 定位触发特征位置判断
纯 JSON→ Path Main直接 JSON 特征提取
↓ 仅日志头+JSON 触发

Step 2a Feature Locator — 特征定位（内嵌）

负责模块：log_feature_locator.py — locate_feature()

职责：LLM 判断分类特征在 header 还是 body

输入：header 聚合统计 + body 字段候选 + 采样日志

输出：

feature_location后续路径
header→ Path A: log_header_processor.py
body→ Path Main: _classify_json_features()
unknown→ FAILED

降级安全：Step 2a 失败时降级为 body，不阻塞流程

↓ 路由结果

路径分支

🟣 Path A — 日志头分类

文件：log_header_processor.py

触发：feature_location=header

流程：

  1. HeaderExtractor.aggregate_headers() 聚合
  2. LLM 分类（log_header_classify.md）
  3. _replace_samples_with_raw() 替换真实样例
  4. 强制 feature_identifier = (\{[\S\s]*\})

🟡 Path Main — JSON 特征提取

文件：log_classifier.py

触发：feature_location=body 或 纯 JSON

流程：

  1. JsonExtractor 提取特征值
  2. aggregate_by_field() 聚合统计
  3. LLM 语义分组（log_classify_feature.md）
  4. postprocess_llm_classification() 后处理
↓

Step 3 Sample Filler — 样本回填

负责模块：log_sample_filler.py

职责：用 feature_identifier 正则从原始日志中匹配样本，补充/覆盖 classification_details

↓

✅ 最终输出 — ClassificationResult

字段说明Path A / Path Main
status成功/失败状态统一
feature_identifierJSON body 匹配正则统一固定 (\{[\S\s]*\})
Diversion_method分类字段中文业务名LLM 填写（如"告警类型"）
classification_details分类详情列表统一
sample完整原始日志行统一（含 syslog 头）
real_samplesJSON body 样例去头后仅 JSON body
⚠️ 关键设计：
  1. feature_identifier 所有 JSON 路径统一为 (\{[\S\s]*\})，后处理强制覆盖，不依赖 LLM 生成。
  2. Diversion_method 为分类字段的中文业务名称，用于 rule_generator.py 子规则命名。
  3. real_samples 提取逻辑（2026-06-05 优化）：
    • JSON 格式：优先用 header_end_marker 分割，fallback 用 {} 定位
    • KV 格式：优先用 feature_identifier 正则提取 body（支持 syslog+KV），降级用 header_end_marker
  4. Step 2a 降级安全：失败时默认 feature_location=body，不阻塞流程。
  5. LLM JSON 输出约束（2026-06-05）：
    • Prompt 层：所有 prompt 添加 JSON Schema 定义，明确输出格式要求
    • API 层：DeepSeek/硅基流动使用 response_format={"type": "json_object"} 强制 JSON
    • 兼容性：智谱 GLM 等 API 依赖 Prompt 约束（不支持 response_format）
