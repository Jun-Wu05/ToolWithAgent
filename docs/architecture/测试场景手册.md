## 第 3 层：Web 冒烟

启动：

```bash
chainlit run web/chainlit_app.py
```

### 场景 1：同文不同 session

| Session | 输入 | 预期 |
|---|---|---|
| 无数据 | `枚举值处理` | 请求上传或澄清，不执行 |
| 只有日志 | `枚举值处理` | 询问目标字段，不执行 |
| 枚举映射表 + 已映射子规则 | `枚举值处理` | 一步 Enum Fill，生成一个配置文件；**未点名字段时直接填充全部目标字段（多 sheet 各填各的），不再追问**（回归 #91） |
| 已有旧枚举结果 | `把这些值做威胁映射` | 不读取旧结果，要求显式值或本次依赖 |

### 场景 2：单一步骤

- `提取 event_type3 的枚举值`：一步 Enum Extract；字段不存在时执行前拦截。
- `做字段映射`：一步 Field Mapping；无字段时请求上传。
- `识别日志类型`：一步 Log Parse；无日志时请求上传。
- `取消 event_type3 的映射`：一步 Remove Mapping。
- `导出当前子规则`：一步 Export，只返回一个文件。

### 场景 3：三步复合计划

输入：`提取 event_type3 的枚举值，把这些值做威胁映射，再填充回 event_type3。`

预期：Enum Extract → Threat Mapping → Fill，日志中可见同一 `plan_id` 和三个不同 `step_id`；最终只渲染一次汇总和一个文件。任一步失败时后续步骤不执行。

### 场景 3b：两步复合计划（提取 + 威胁映射，回归 #79）

输入：`把alarm_name的枚举值提取出来，并且进行威胁类型映射`（会话有日志、无枚举映射表）。

预期：Enum Extract → Threat Mapping 两步依赖链，不生成 Fill；威胁映射使用内置威胁分类表，界面输出枚举值表格和威胁映射表格，**不因缺少枚举映射表而追问**。

### 场景 4：歧义与帮助

- 二选一或冲突指令返回 Clarification，业务执行器调用数为零。
- 新手帮助返回 Guidance，PlanExecutor 调用数为零。
- Planner 服务不可用时明确说明本次未执行任何操作。

### 场景 5：确定性入口

- 上传文件只更新会话事实，不因旧 fill mode 劫持上传。
- “开始枚举填充”按钮与等价自然语言产生相同领域结果。
- 参数不足的威胁填充按钮明确要求目标字段，不劫持下一条消息。
- 精确命令 `清空数据` 直接清空；普通句子 `清空 event_type3 的映射` 仍交 Planner。

## 第 4 层：真实模型稳定性与全业务验收

对场景 1–4 的核心语料每条连续运行三次，记录：

- schema 是否合法；
- 是否错误执行；
- 是否出现错误状态变更；
- 计划或安全追问是否符合预期；
- Planner 延迟、执行延迟和 token。

首版不以延迟/token 阻断，但任何 schema 非法、错误执行或错误状态变更都阻断发布。

关闭架构迁移父 PRD 前，另通过真实 Chainlit UI 验证：模型设置、Excel 上传、日志类型提取、字段映射、枚举提取、威胁类型映射、填充、字段调整、导出、Base64 直接操作、失败追问和跨轮可引用会话产物。逐项检查用户提示、进度、Session 变化、模型调用阶段、稳定错误码、表格、下载文件名和解码后的配置语义；任何差异均阻断发布。
