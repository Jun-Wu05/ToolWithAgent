## 1. 项目定位

**数据映射智能助手** — 面向安全日志分析的 AI 辅助工具，通过 LLM Agent 实现：

- 标准字段映射（将异构日志字段映射到统一标准字段）
- 威胁类型标准化（威胁告警归一化到威胁知识库）
- 枚举提取与填充（从日志中提取映射规则词对，或批量填充枚举映射表）
- 日志格式识别与特征分类（识别日志数据结构类型，提取统计特征）
- 结构化指纹向量知识库（基于特征提取结果的快速检索与复用）

交付形式：**Chainlit Web 聊天界面**（也保留 Tkinter GUI，已归档至 `reference/gui/`）。

## 3. 核心流程

### 3.1 路由分发

`web/route_config.py` 从 `config/route_keywords.json` 加载关键词，根据用户消息匹配意图：

| 路由 | 触发关键词 | to_model 参数 |
|------|-----------|--------------|
| 日志解析 | `日志解析` `log_parser` `识别格式` `特征提取` | `log_parser_agent` |
| 威胁类型 | `威胁类型` `attack_type` `threat_type` | `threat_agent` |
| 枚举填充 | `枚举值填充` `枚举填充` `enrich` `补全` | `enum_fill_agent` |
| 枚举提取 | `枚举字段提取` `枚举提取` `extract` `抽取` | `enum_extract_agent` |
| 字段映射 | 默认回退 | `field_mapping_agent` |

### 3.2 请求生命周期

```
用户输入 → 路由匹配 → 构建 LLM 输入
→ call_team() → Agno Team 调度
→ Agent 推理 → 工具调用 (agent/tools/)
→ 结果解析 → 表格渲染 → 用户输出
```

### 3.3 日志解析管道

```
Step 1: _do_identify_log_format()
  → 加载 agent/prompts/log_format_identify.md
  → LLM 识别日志格式类型 (JSON/CSV/CEF/KeyValue/Header+JSON 等)
  → 返回 format_type, format_detail, regex_pattern

Step 2: _aggregate_by_log_type()
  → 基于 format_info 正则匹配分组
  → 统计 matched_lines / total_lines

Step 3: _do_classify_log_features()
  → 加载 agent/prompts/log_classify_feature.md
  → LLM 提取字段特征 (field_name, value_count, data_type, sample_values)
  → 输出结构化特征 JSON

Step 4: 存入向量知识库
  → generate_structured_fingerprint() 生成索引
  → 后续相似格式直接匹配复用
```

## 6. 错误处理策略

```
LLM 调用失败
├─ RetryPolicy (最多 3 次，指数退避)
├─ CircuitBreaker (5 次失败后熔断 60s)
└─ ModelFallback (SiliconFlow → DeepSeek)
```

关键操作（Base64 解码、JSON 解析、API 调用）均有 `try-except` 包裹在具体异常类型上。

---

## 7. 安全注意事项

- API 密钥仅从环境变量和 `.env` 文件读取，不硬编码
- `.env`、`*.pem`、`*secret*`、`*credential*`、`*key*` 文件禁止读取/修改
- `config/` 下的 `.db` 文件通过 `.gitignore` 排除（防止向量知识库被误提交）
