# Pipeline 架构代码规范

## 1. 核心原则：完全信任上游，快速失败

**架构理念**：
- Pipeline 的每个步骤应该完全信任上游步骤的结果
- 如果上游步骤失败或返回不完整的信息，应该立即报错，而不是尝试兜底
- 兜底策略会隐藏问题，导致系统不可预测

**示例**：
```python
# ❌ 错误：使用默认值兜底
field_delimit = format_info.get("delimit", " ") or " "

# ✅ 正确：强制上游提供完整信息
if not format_info.get("delimit"):
    raise ValueError("format_info 中缺少 delimit 字段，Step 1 识别不完整")
field_delimit = format_info["delimit"]
```

---

## 2. 禁止硬编码配置参数

**禁止硬编码的内容**：
- 分隔符（如 `field_delimit = " "`、`kv_delimit = "="`）
- 格式标识符（如 `format_type = "json"`）
- 字段名（如 `feature_field = "log_type"`）
- 任何应该从配置或上游步骤获取的参数

**例外情况**：
- 常量定义（如 `MAX_LINES = 2000`）
- 错误消息字符串（如 `"format_info 为空"`）

---

## 3. 禁止兜底策略

**什么是兜底策略**：
- 尝试多种默认值（如 `if failed: try another delimiter`）
- 静默降级（如 `except: use default`）
- 自动推断（如 `if not provided: auto-detect`）

**为什么禁止**：
- 隐藏上游步骤的问题
- 导致系统行为不可预测
- 增加维护成本
- 降低泛化能力

**示例**：
```python
# ❌ 错误：兜底策略
if matched_lines == 0:
    logger.warning("使用默认分隔符匹配失败，尝试冒号分隔符")
    extractor = KvExtractor(field_delimit=field_delimit, kv_delimit=":")
    ...

# ✅ 正确：快速失败
if matched_lines == 0:
    logger.error(f"匹配失败：field_delimit={field_delimit}, kv_delimit={kv_delimit}")
    raise ValueError(f"分隔符识别错误：field_delimit={field_delimit}, kv_delimit={kv_delimit}")
```

---

## 4. 强制参数传递

**原则**：
- 每个步骤必须显式传递所有必要的参数
- 不要依赖默认值或隐式传递
- 参数名称必须明确表达其用途

**示例**：
```python
# ❌ 错误：不传递 header_end_marker
aggregation = extractor.extract_and_aggregate(logs_str, feature_field)

# ✅ 正确：显式传递所有参数
aggregation = extractor.extract_and_aggregate(
    logs_str=logs_str,
    feature_field=feature_field,
    header_end_marker=header_end_marker,
)
```

---

## 5. 强制参数校验

**原则**：
- 函数开始时校验所有必要参数
- 如果参数缺失或无效，立即报错
- 不要静默使用默认值

**示例**：
```python
# ❌ 错误：不校验参数
def extract_value(self, line: str, feature_field: str) -> Any:
    return self._pattern.search(line)

# ✅ 正确：校验参数
def extract_value(self, line: str, feature_field: str) -> Any:
    if not line or not line.strip():
        raise ValueError("line 不能为空")
    if not feature_field or not feature_field.strip():
        raise ValueError("feature_field 不能为空")
    return self._pattern.search(line)
```

---

## 6. Pipeline 步骤职责划分

**每个步骤的职责**：
- Step 1 (LLM): 识别格式、分隔符、字段名
- Step 2a (LLM): 定位特征位置
- Step 2 (Code): 路由到正确的提取器
- Step 2b (Code): 聚合特征值
- Step 2c (LLM): 语义分组
- Step 3 (Code): 填充样本

**原则**：
- 每个步骤只做自己的事情
- 不要跨步骤做决策
- 不要尝试"修复"上游步骤的结果

---

## 7. 错误处理原则

**原则**：
- 如果上游步骤失败，立即报错
- 不要尝试"修复"或"兜底"
- 错误消息必须包含足够的上下文信息

**示例**：
```python
# ❌ 错误：静默处理错误
try:
    field_delimit = format_info["delimit"]
except KeyError:
    field_delimit = " "  # 静默使用默认值

# ✅ 正确：明确报错
try:
    field_delimit = format_info["delimit"]
except KeyError:
    raise ValueError(
        f"format_info 中缺少 delimit 字段，Step 1 识别不完整。"
        f"format_info={format_info}"
    )
```

---

## 8. 日志记录原则

**原则**：
- 记录所有关键决策（如参数选择）
- 记录所有错误（包含完整上下文）
- 不要记录敏感信息（如 token、密码）

**示例**：
```python
logger.info(
    f"[_classify_kv_features] Step 2 参数: "
    f"format_info={format_info}, "
    f"field_delimit='{field_delimit}', "
    f"kv_delimit='{kv_delimit}', "
    f"feature_field='{feature_field}'"
)

logger.error(
    f"[_classify_kv_features] 解析 format_info 失败: {e}. "
    f"format_info={format_info}, "
    f"format_type={format_type}, "
    f"format_detail={format_detail}"
)
```

---

## 9. 代码审查清单

在修改 Pipeline 代码时，必须检查：
- [ ] 是否有硬编码的分隔符、格式标识符、字段名？
- [ ] 是否有兜底策略（尝试多种默认值）？
- [ ] 是否有隐式参数传递（不传递关键参数）？
- [ ] 是否缺少参数校验？
- [ ] 错误消息是否包含足够的上下文？
- [ ] 日志记录是否包含关键决策？

---

## 10. 违反规范的后果

如果违反上述规范：
1. 立即停止并说明违反的规则编号
2. 提供修复方案
3. 等待用户确认后再继续

## 附录：Pipeline 流程图

```
Step 1 (log_format_identifier.py) → 识别格式
  ├─ 返回: format, format_detail, delimit, tab, header_end_marker, feature_field, has_header, has_header_feature, feature_location
  └─ Prompt: log_format_identify.md
  
  ↓ 如果 has_header=True
  
Step 2a (log_feature_locator.py) → 特征定位
  ├─ 返回: feature_location, feature_field, reason, body_candidates
  └─ 使用 delimit 和 tab 参数
  
  ↓
  
Step 2 (log_classifier.py) → 特征分类
  ├─ Path A (header): 特征在日志头中
  ├─ Path Main (body): JSON 特征在 body 中
  └─ Path KV (body): KV 特征在 body 中
      └─ 使用 format_info={delimit, tab}
  
  ↓
  
Step 2b (aggregator.py + extractor.py) → 聚合
  ├─ 使用 extractor 提取特征值
  ├─ 使用 header_end_marker 剥离日志头
  └─ 返回聚合结果
  
  ↓
  
Step 2c (LLM) → 语义分组
  
  ↓
  
Step 3 (log_sample_filler.py) → 填充样本
```
