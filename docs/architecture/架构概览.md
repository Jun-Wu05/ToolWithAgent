## 1. 项目定位

**数据映射智能助手** — 面向安全日志分析的 AI 辅助工具，通过 LLM Agent 实现：

- 标准字段映射（将异构日志字段映射到统一标准字段）
- 威胁类型标准化（威胁告警归一化到威胁知识库）
- 枚举提取与填充（从日志中提取映射规则词对，或批量填充枚举映射表）
- 日志格式识别与特征分类（识别日志数据结构类型，提取统计特征）
- 结构化指纹向量知识库（基于特征提取结果的快速检索与复用）

交付形式：**Chainlit Web 聊天界面**（也保留 Tkinter GUI，已归档至 `reference/gui/`）。

## 2. 系统架构图

```text
Chainlit Web UI
├─ user_message_handlers.py ──> PlannerAgent ──> PlanDecision
├─ file_handlers.py ──────────> application/session_state.py
├─ application/session_projection.py ──────────> SessionFacts
└─ action_callbacks.py ───────> StepSpec
                                      │
                                      ▼
                         application/PlanExecutor
                                      │
          ┌───────────────────────────┼───────────────────────────┐
          ▼                           ▼                           ▼
 application/LogParseAdapter    Fill/Remove Adapter    application/ExportAdapter
          │                           │                           │
   日志领域 Pipeline             共享领域函数                 配置产物
          └───────────────────────────┴───────────────────────────┘
                                      │
                               ExecutionReport
                                      │
                                  Renderer
```

`SessionFacts` 是 session 状态判断的唯一投影。其不可变类型契约位于 `contracts/session_facts.py`，会话读取、可用字段汇总、配置目标绑定和安全产物目录投影由 `application/session_projection.py` 统一实现。Contracts 不读取运行时会话，也不依赖 Web、Application、Chainlit 或 Agent 领域实现。

`SessionState`、`PlanExecutor`、结果账本推进和无界面进度空实现归属 Application；执行核心只依赖 Contracts 与标准库。Web 组合根通过 `ExecutionPolicy` 注入事件名和日志特征字段等现有领域预检。日志解析与导出 tracer 已迁至 Application Adapter，并保持模型调用顺序、分类结果、文件名、JSON/Base64 字节和稳定错误码不变；字段映射、枚举、威胁、Fill/Remove 等其余业务 Adapter 仍在 `web/`，由后续切片迁移。

## 3. 核心流程

### 3.1 自然语言理解

每条自然语言业务请求恰好调用一次 PlannerAgent。Planner 输入为用户原文、有限历史和 SessionFacts；输出为 ExecutePlan、Clarification 或 Guidance。Planner 失败时不执行，也不回退关键词路由。

### 3.2 请求生命周期

```text
用户输入 → Application 会话投影 → SessionFacts → PlannerAgent → PlanDecision
→ PlanExecutor 校验与依赖解析 → StepAdapter 执行
→ ExecutionReport → 一次汇总与最多一个配置文件
```
### 3.3 日志解析管道

```text
LogParseStep → Application LogParseAdapter
  → 格式识别（显式分类特征字段不改变此调用阶段）
  → 日志头/体定位与 JSON、KV 或 Header 分类策略
  → 真实样本回填
  → session.log_classification 一次性提交
  → LogClassificationArtifact → ExecutionReport

后续跨轮 ExportStep
  → 重新投影 SessionFacts
  → 入口规则或子规则生成
  → 既有 Base64 规则格式
```

五个日志 Pipeline Prompt 文件和加载实现均位于 `agent/prompts/`，路径基于包位置而非当前工作目录；缺失时继续返回空字符串。`agent/core/prompts.py` 仅为迁移期同对象兼容入口。

## 6. 错误处理策略

```
LLM 调用失败
├─ RetryPolicy (最多 3 次，指数退避)
├─ CircuitBreaker (5 次失败后熔断 60s)
└─ ModelFallback (SiliconFlow → DeepSeek)
```

关键操作（Base64 解码、JSON 解析、API 调用）均有 `try-except` 包裹在具体异常类型上。

---

## 7. 安全注意事项

- API 密钥仅从环境变量和 `.env` 文件读取，不硬编码
- `.env`、`*.pem`、`*secret*`、`*credential*`、`*key*` 文件禁止读取/修改
- `config/` 下的 `.db` 文件通过 `.gitignore` 排除（防止向量知识库被误提交）
