# ToolWithAgent 架构概览

> **文档版本**：2026-08-31
> **对应分支**：`codex/issue144-documentation-zero-regression`
> **架构决策**：ADR-0009

---

## 1. 项目定位

ToolWithAgent 是面向安全日志和解析配置的数据映射智能助手，交付入口是 Chainlit Web。系统把自然语言转换为类型化计划，组合日志类型提取、字段映射、枚举提取、威胁类型映射、填充、字段调整与导出，并把结果写回当前会话的主数据和可引用会话产物。

## 2. 语义架构

```text
Chainlit Web
  输入 / 生命周期 / 进度 / 渲染
                 │
                 ▼
Application Request Runtime
  Planner 调用 / 历史 / SessionFacts / 运行时组合
                 │
                 ▼
Application Execution Runtime ───────> Contracts
  校验 / 依赖 / 结果账本 / 失败关闭     类型与不变量
                 │
                 ▼
Application Adapters
  StepSpec 翻译 / 领域调用 / Session 原子写回
                 │
      ┌──────────┼──────────┐
      ▼          ▼          ▼
专业 Agent   领域函数/Pipeline   Skills 脚本
```

依赖方向是 `web → application → contracts`。Application 核心运行时只依赖 Contracts 与标准库；Application Adapters 可以在明确接缝处依赖 Agent、领域函数和 Skills。Application、Contracts、Agent 与 Skills 均不得反向导入 Web 或 Chainlit。

## 3. 运行时所有权

| 边界 | 当前所有者 | 职责 |
|---|---|---|
| 自然语言与确定性请求 | `application/request_runtime.py` | 一次 Planner 调用、组合执行器、历史更新、清空命令与进度阶段 |
| 类型化计划执行 | `application/execution.py` | 语义校验、依赖解析、步骤推进、结果账本和失败关闭 |
| 领域预检策略 | `application/execution_policy.py` | 日志特征字段、固定字段等领域校验，不把规则写入核心执行器 |
| 会话与事实 | `application/session_state.py`、`application/session_projection.py` | 主数据生命周期、可引用会话产物与安全 SessionFacts |
| 业务适配器 | `application/adapters/` | 12 类步骤的唯一生产实现及 `create_default_adapters` 组合入口 |
| 模型/字段/文件入口 | `application/model_runtime.py`、`application/field_runtime.py`、`application/file_input.py` | Team 生命周期、字段检索、确定性解码与主数据提交 |
| Chainlit 适配 | `web/` | 文件/文本输入、生命周期、设置、Action、进度和结果渲染 |
| 类型契约 | `contracts/` | PlanDecision、StepSpec、ExecutionReport、SessionFacts、ProgressEvent |

## 4. 核心请求流程

```text
用户原文
  → run_user_request
  → build_session_facts
  → PlannerService.plan（恰好一次）
  → PlanDecision
  → create_default_adapters + create_plan_executor
  → PlanExecutor.execute
  → StepAdapter
  → ExecutionReport
  → Web Renderer（一次汇总）
```

确定性 Action 把完整参数转换为 StepSpec 后调用 `run_deterministic_plan`，不调用 Planner。精确清空命令由请求运行时直接清理 Session；普通自然语言仍进入 Planner。任一步失败或待输入后立即停止，禁止关键词路由或旧 Session 键兜底。

## 5. 业务切片

- **日志类型提取**：LogParseAdapter 调用日志 Pipeline，按固定顺序识别格式、分类、回填样本并提交 `log_classification`。
- **字段映射**：FieldMappingAdapter 调用 FieldMappingBatchRunner，保持每批 25、最大并发 3、超时拆批、可重试错误、漏字段补查和一次性写回。
- **枚举/威胁/填充**：独立 Adapter 只消费显式步骤依赖或白名单可引用会话产物；Fill 写入 `normalize[].mappings`。
- **字段调整**：FieldSkillAdapter 通过声明式注册表加载 `skills/*/scripts/`，脚本是变换逻辑的单一事实源。
- **导出**：ExportAdapter 保持各业务既有 JSON 根结构、键顺序、中文编码、Base64 字节和下载语义。

## 6. Prompt、资源与模型

全部 Prompt 文件及公开加载器位于 `agent/prompts/`，资源路径以包位置为基准，不依赖当前工作目录。模型提供商参数由 ProviderSpec 注册表单点声明；`application/model_runtime.py` 负责会话设置覆盖、Team 懒初始化与重置。字段 embedding 固定使用硅基流动，与聊天模型提供商分离。

## 7. 安全与可观测性

- SessionFacts 不暴露 API key、真实文件路径、配置内容或原始敏感值。
- 每会话消息通过 `asyncio.Lock` 串行执行。
- 用户可见进度只呈现安全阶段，不暴露隐藏推理或结构化模型输出。
- 模型、批次、重试和 Token 日志保留稳定追踪字段并经过脱敏。
- 普通开发日志可调整措辞；稳定错误码、中文业务名称、进度心跳和 Token 桥接不得丢失或重复。
