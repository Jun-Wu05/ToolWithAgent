# 威胁类型映射与字段处理完整指南

## 一、核心功能概览

本系统提供完整的威胁类型映射和字段枚举值处理功能，主要包括：

1. **威胁类型标准化**：将各种不规范的威胁类型描述转换为标准名称
2. **字段枚举值映射**：为JSON文件中的字段动态添加枚举值映射关系
3. **Excel数据处理**：支持从Excel文件读取映射规则并应用到JSON数据
4. **正则匹配支持**：提供灵活的匹配模式，支持精确匹配和模糊匹配

### 核心组件
- `ThreatTypeManager`：威胁类型管理器，负责标准化匹配
- `DataProcessor`：数据处理器，负责Excel读取和JSON处理
- `FieldMappingHandler`：字段映射处理器，负责枚举值添加

## 二、威胁类型标准化逻辑

### 2.1 配置文件结构

系统使用 `threat_type_config.json` 配置文件，包含：

```json
{
  "threat_types": [
    {
      "name": "XSS攻击",
      "patterns": ["xss", "跨站脚本", "cross-site scripting"]
    }
  ],
  "special_cases": {
    "跨站脚本攻击": "XSS攻击",
    "xss": "XSS攻击"
  },
  "separators": ["/", ",", "，", "或", "和", "、"],
  "default_type": "其他"
}
```

### 2.2 匹配策略

#### A. REGULAR 类型路径（精确匹配）
如果 `mapping_type` 为 `REGULAR`，执行精确匹配：

1. **严格匹配**：输入值必须与配置文件中的 `name` 完全一致（忽略大小写）
2. **后缀容错**：如果输入值以 "攻击" 结尾且匹配失败，尝试去除 "攻击" 后缀再次匹配
3. **失败处理**：返回默认类型（"其他"）

#### B. 普通路径（多级模糊匹配）
执行多级模糊匹配策略，优先级如下：

1. **特殊情况映射**：检查 `special_cases` 字典
2. **标准类型匹配**：
   - 名称直配：`Input == Name` (忽略大小写)
   - 部分包含：`Input` 包含 `Name` 或 `Name` 包含 `Input`
   - 正则模式匹配：使用配置文件中的 `patterns`
3. **默认类型模式匹配**：检查默认类型（"其他"）的正则模式
4. **输入清洗与重试**：
   - 正则字符清洗：提取中文/英文/数字部分
   - 分隔符处理：分割输入后对每部分进行匹配
   - 括号处理：移除括号内容后重试
5. **最终兜底**：返回默认类型（"其他"）

### 2.3 性能优化

- **LRU缓存**：使用 `@lru_cache(maxsize=1024)` 缓存匹配结果
- **预编译正则**：启动时预编译所有正则表达式
- **索引结构**：构建名称索引和模式索引，提升查找效率

## 四、Excel数据处理规范

### 4.1 工作表识别

系统会检查Excel工作表名称，自动识别威胁类型表：

**触发条件**：工作表名称包含以下关键词（不区分大小写）：
- `threat_type`
- `threatType` 
- `威胁类型`

**行为差异**：
- **威胁类型表**：启用标准化逻辑，将映射值转换为标准威胁类型
- **普通表**：保持1:1映射，不进行标准化处理

### 4.2 数据列处理

读取每行的前三列：

| 列位置 | 字段名 | 说明 | 处理规则 |
|--------|--------|------|----------|
| 第1列 | Mapping Type | 映射类型 | 默认为 `EQUAL`，支持 `REGULAR` |
| 第2列 | Org Value | 原始匹配值 | `REGULAR` 类型自动添加 `.*` 通配符 |
| 第3列 | Mapping Value | 目标映射值 | 威胁类型表会进行标准化处理 |

### 4.3 标准化处理

对于威胁类型表：


### 5.2 关键方法实现

#### 威胁类型匹配核心逻辑

```python
def _match_single_part(self, part: str) -> str:
    """单个部分的匹配逻辑"""
    part_lower = part.lower()
    
    # 1. 特殊情况映射
    for key, target_type in self.special_cases.items():
        if key.lower() in part_lower or part_lower in key.lower():
            return target_type
    
    # 2. 精确名称匹配
    if part_lower in self._name_index:
        return self._name_index[part_lower]
    
    # 3. 部分包含匹配
    for name in self._name_index.values():
        if name.lower() != self.default_type.lower():
            if part_lower in name.lower() or name.lower() in part_lower:
                return name
    
    # 4. 正则模式匹配
    for compiled, name in self._pattern_index:
        if name.lower() != self.default_type.lower():
            if compiled.search(part):
                return name
    
    return self.default_type
```

#### 映射添加逻辑

```python
def add_mappings_to_index(self, data, new_mappings, index_val) -> bool:
    """将映射添加到指定索引位置"""
    new_mappings_dict = {mapping['orgValue']: mapping for mapping in new_mappings}
    
    for rule in data:
        normalize_items = rule.get('normalize', [])
        for norm_item in normalize_items:
            if norm_item.get('index') == index_val:
                mappings = norm_item.setdefault('mappings', [])
                
                # 增量更新逻辑
                existing_org_values = {m['orgValue'] for m in mappings}
                
                mappings_to_add = []
                updated_count = 0
                
                for org_val, m in new_mappings_dict.items():
                    if org_val not in existing_org_values:
                        mappings_to_add.append(m)
                    else:
                        # 更新已存在的映射
                        existing_idx = next((i for i, existing_m in enumerate(mappings) 
                                          if existing_m['orgValue'] == org_val), None)
                        if existing_idx is not None:
                            existing_mv = mappings[existing_idx].get('mappingValue', '')
                            new_mv = m.get('mappingValue', '')
                            if new_mv and existing_mv != new_mv:
                                mappings[existing_idx]['mappingValue'] = new_mv
                                updated_count += 1
                
                # 添加新映射
                if mappings_to_add:
                    mappings.extend(mappings_to_add)
                
                return True
    
    return False
```

## 七、常见问题与解决方案

### Q1：如何处理重复的映射项？
**A**：系统会检查映射项的 `orgValue` 字段，若已存在则跳过添加。在 `add_mappings_to_index` 方法中实现了去重逻辑。

### Q2：如何修改默认映射值？
**A**：通过修改 `threat_type_config.json` 文件中的 `default_type` 属性，默认为 "其他"。

### Q3：支持哪些Excel格式？
**A**：支持 `.xlsx` 和 `.xls` 格式，要求数据位于第一列，可选择是否包含表头。

### Q4：如何扩展到其他字段？
**A**：修改代码中的字段名检查逻辑，将 `"field" == "threat_type"` 替换为可配置的字段名，或传入字段名参数。

### Q5：为什么某些威胁类型映射到"其他"？
**A**：可能的原因：
- 配置文件中没有对应的匹配模式
- 输入值过于特殊，无法通过现有规则匹配
- 需要在 `special_cases` 中添加特殊映射

### Q6：如何提高大文件处理性能？
**A**：系统已实现以下优化：
- Excel文件缓存机制
- LRU缓存减少重复计算
- 预编译正则表达式
- Base64文件大小检查和警告
