# PRD：会话数据集与枚举映射附件生命周期

## 问题陈述

同一 Chainlit 会话允许连续上传日志 Excel、Base64/TXT 配置和枚举映射 Excel。当前状态以零散字段递增覆盖：新的主数据只覆盖部分 `decoded_*` 字段，旧日志分类、子规则和映射结果仍会进入 `SessionFacts`；枚举 Excel 虽会覆盖单一预览缓存，已经填入配置的旧规则仍按 `orgValue` 去重保留。用户因此可能看到新输入与旧派生结果混合，或下载与最新枚举 Sheet 不一致的配置。

## 解决方案

建立明确的会话数据集生命周期：有效主数据经完整解析后原子替换当前数据集，并使旧数据集的附件和派生结果失效；无效上传保持旧状态不变。枚举映射 Excel 作为当前主数据的附件，以 Sheet 名为身份键组成映射集合；不同 Sheet 累积，同名 Sheet 完整替换。通过枚举贡献账本精确撤销旧 Sheet 写入的规则，并在附件变化到重新填充期间阻止过期配置被导出或继续使用。

## 用户故事

US-1：作为规则配置操作者，我想在同一会话上传新的有效主数据时完整替换旧数据集，以便后续事实、映射和下载只基于当前文件。

US-2：作为规则配置操作者，我想在上传无效主数据时继续保留当前有效数据集，以便一次格式错误不会破坏已有工作。

US-3：作为规则配置操作者，我想让枚举映射附件只隶属于当前主数据，以便切换数据集后不会误用旧文件的枚举规则。

US-4：作为规则配置操作者，我想分次上传不同目标字段的枚举 Sheet 并累积使用，以便最终配置包含当前主数据与全部已确认的枚举映射。

US-5：作为规则配置操作者，我想让新上传的同名 Sheet 完整替换旧版本，以便修改、删除和新增的映射行都准确反映到下一次填充结果。

US-6：作为规则配置操作者，我想在同名 Sheet 重填时保留主数据原有及其他来源的映射，以便一次附件更新不会破坏无关配置。

US-7：作为规则配置操作者，我想在枚举附件更新但尚未重新填充时阻止旧配置导出，以便不会误把过期结果当作最新结果。

US-8：作为规则配置操作者，我想让多 Sheet 工作簿整体验证和提交，以便不会形成一部分来自新版、一部分来自旧版的混合附件状态。

US-9：作为规则配置操作者，我想在切换主数据时清空 Planner 的旧文件对话上下文，但保留会话任务历史，以便语义上下文正确且操作轨迹连续。

## 实现决策

### 主数据解析后原子提交

Base64/TXT 与日志 Excel 均先在局部变量中完成读取、解析和业务校验；只有成功结果可以提交给会话状态。提交入口集中清除旧主数据、日志分类、字段/枚举/威胁派生结果、临时导出、枚举映射集合、枚举贡献账本、过期标记和 Planner 对话历史，再一次性安装新主数据。Team、供应商、API、模型配置以及位于 Chainlit 会话外层的任务账本不变。

### 枚举工作簿按 Sheet 原子合并

枚举工作簿的每个 Sheet 名等于目标字段身份。工作簿全部 Sheet 可读取且每个 Sheet 至少产生一条有效规则时，才把解析结果提交到当前枚举映射集合；不同 Sheet 加入集合，同名 Sheet 以新 Sheet 全量替换，未出现在本次工作簿的其他 Sheet 保留。文件名不参与身份判断。任一 Sheet 失败时整个工作簿不改变会话状态。

### 枚举贡献与过期配置

会话按“配置来源 + Sheet”记录上一次实际写入的枚举规则。有效附件提交后，已有枚举派生配置进入过期状态；上传仍只建立结构化事实，不自动执行填充。过期配置不得导出或作为后续配置来源。再次填充时先从当前配置精确移除贡献账本记录的旧规则，再应用当前 Sheet 版本并刷新账本；主数据自带、威胁映射及其他 Sheet 的贡献保持不变。所有待更新 Sheet 成功后恢复配置有效状态。

### 事实投影与执行边界

`SessionFacts` 只投影当前主数据和当前有效派生结果。Planner 契约、字段映射算法、下载命名和 `ProgressEvent` 不变。Adapter 不读取旧配置作为兜底；上传入口不执行填充业务。

### 交付切片

第一切片修复主数据原子替换及状态清除，对应现有 Issue #101。第二切片实现枚举映射集合、贡献账本、过期门禁和同名 Sheet 覆盖，依赖第一切片已合并。两个切片分别使用独立 Issue、分支、测试、PR 和人工复测。

## 测试决策

### 主数据跨上传全链路 seam

通过 `handle_file_upload → SessionState → build_session_facts → PlanExecutor/字段映射` 的公开行为验证：旧日志 Excel 切换到有效 Base64/TXT、旧配置切换到有效日志 Excel、无效上传回滚、字段来源、Planner 历史清除和任务账本保留。测试只替换文件/模型/Chainlit 外部边界，不模拟状态提交核心。

### 枚举附件跨上传全链路 seam

通过真实工作簿解析、上传入口、枚举填充 Adapter 和导出 Adapter 验证：不同 Sheet 累积、同名 Sheet 修改/删除/新增、其他来源 mappings 保留、多 Sheet 原子拒绝、过期配置禁止导出，以及重新填充后恢复。一个可观察行为对应一个 RED→GREEN 循环。

### 会话状态契约回归

扩展现有 `SessionState` 契约测试，覆盖状态组的清除/保留矩阵和未知字段门禁。完整回归必须继续通过 Planner、字段映射、下载命名、进度事件和现有输出格式测试，并执行 `git diff --check`。

## 范围外

- 不修改 Planner 的类型化计划或提示词契约。
- 不重构完整派生操作重放管道。
- 不改变字段映射算法、下载命名、`ProgressEvent` 或业务输出格式。
- 不处理“实际更新 normalize 项数”的统计文案。
- 不提供跨主数据复用枚举附件或由用户选择保留附件的交互。
- 不在上传枚举 Excel 后自动执行填充。

## 补充说明

- UI 模式：headless；不涉及页面、States 矩阵或设计稿。
- 父 PRD 是两个功能 Issue 的接口与行为唯一权威来源。
- Issue #101 的旧验收项“主数据切换后保留枚举映射 Excel”由本 PRD 明确替代为“一并清除”。
- 本决策细化现有会话状态边界，不新增难以逆转的架构选择，因此无需新增 ADR。
