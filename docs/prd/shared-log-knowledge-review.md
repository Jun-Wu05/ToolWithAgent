# PRD：公共日志解析知识库与管理者审核

## 问题陈述

日志类型提取已经能够识别日志格式、定位分类特征字段并生成字段路径或正则，但每次面对相同结构的主数据仍会重复调用模型完成相同的格式理解和提取规则发现。仓库已有日志模式存储与检索雏形，实际生产链路却只写不读；当前保存的结构化指纹与查询时生成的原始日志指纹语义不一致，调用方也没有写入 embedding，导致向量 sidecar 不存在、检索无法命中。SQLite、NumPy 和 JSON sidecar 三份状态还带来额外一致性风险。

直接复用历史分类结果同样不正确：日志类型、数量、覆盖率和真实样例属于某次主数据，不能作为其他用户上传数据的事实。仅凭相似度或模型自报置信度自动公开解析方法也会污染公共知识——技术校验只能证明规则能执行，无法证明模型选择的分类特征字段符合用户的业务意图。

系统因此需要把“候选发现”“确定性验证”“用户申请”和“管理者批准”分开：所有用户可以基于当前成功结果发起日志知识申请，只有管理者审核批准的日志解析知识才能供全体用户检索；每次命中仍必须在本次主数据上回放并重新计算事实。

## 解决方案

建立部署范围内共享的公共日志知识库，以 SQLite 作为单一事实源，保存日志结构、选择模式、分类特征字段、可执行解析配方、审核状态与受限原始日志样例。候选检索不使用语义 embedding：先按格式与选择模式分桶，优先匹配规范化结构 hash；无精确结果时，以结构 token 的 Jaccard/位置化模板相似度取少量候选。相似度只负责排序，不能直接构成命中。

日志类型提取开始时只查询“已批准”知识。候选必须在当前主数据上确定性回放，通过配方版本、字段路径或正则、捕获组、覆盖率与结果非空校验后才算命中；命中后跳过昂贵的模型发现调用，但仍全量计算当前日志类型、数量、覆盖率和真实样例。候选失败或知识库不可用时，只回退一次现有完整流程。

完整流程产生的新配方不会自动公开。结果达到准入标准后，普通用户在现有 Chainlit 结果消息中点击“申请加入知识库”，形成“待审核”申请。管理者通过只监听本机、带启动期随机令牌的一页式审核台查看结构、规则、覆盖率和最多 10 条原始日志，批准、拒绝或替代已有知识。只有“已批准”记录参与检索。

## 用户故事

US-1：作为普通用户，我想让系统自动复用已经批准且适用于当前主数据的日志解析知识，以便减少重复的模型调用和等待时间。

US-2：作为普通用户，我想让知识命中后仍根据当前主数据重新计算日志类型、数量、覆盖率和真实样例，以便不会收到其他用户历史文件中的结果。

US-3：作为普通用户，我想在日志类型提取结果可靠时点击“申请加入知识库”，以便把可复用的解析方法提交给管理者审核，而不是自动公开。

US-4：作为普通用户，我想在申请不满足准入条件、结果已经失效、相同申请已存在或知识已经批准时收到明确反馈，以便知道系统是否真的创建了新申请。

US-5：作为管理者，我想查看待审核申请的结构、选择模式、分类特征字段、解析配方、覆盖率、提取结果和原始日志，以便判断其是否适合全体用户复用。

US-6：作为管理者，我想批准或拒绝申请，并让拒绝操作必须记录理由，以便公共知识的变更可追溯。

US-7：作为管理者，我想在同一日志结构和选择模式已有批准知识时比较竞争配方，并通过一次原子操作批准新配方、拒绝旧配方，以便任一时刻只有一个生效版本。

US-8：作为管理者，我想让每份申请最多保留 10 条去重原始日志并可手动清理已拒绝记录，以便兼顾后期调试、磁盘使用和审计安全。

US-9：作为显式指定分类特征字段的用户，我想让这类知识只在以后显式指定同一字段时复用，以便我的主观分类选择不会改变其他用户的自动探测结果。

US-10：作为普通用户，我想在知识库无候选、候选失效、数据库损坏或审核数据不兼容时安全回退现有日志类型提取，以便知识功能不能降低当前主路径的可靠性。

US-11：作为部署机器操作者，我想通过仅本机可访问、启动时带随机令牌的管理审核台处理申请，以便第一版无需建设账号、密码和角色系统也能隔离审核权限。

US-12：作为本地开发者或单实例部署者，我想默认直接使用项目现有数据库路径，并可通过环境配置指向持久化目录，以便现在可以本机验证、未来部署时无需修改业务代码。

US-13：作为现有知识数据维护者，我想保留旧数据库及原始样例，并让可重建的旧记录进入待审核、不可重建记录保持不可检索，以便升级不把未经审核的历史内容直接公开。

US-14：作为维护者，我想观察候选、命中、拒绝原因、回退和审核状态变化，同时确保原始日志不进入运行日志或其他用户的模型请求，以便定位效果问题而不扩大敏感数据暴露面。

## UI 与设计要求

**UI 模式**：`spec-driven`。UI 设计描述是编码的唯一权威来源；不制作默认态或状态变体设计稿。品牌视觉、字体、表面与通用原语复用 `docs/design/DESIGN.md`，本 PRD 不重复其 Token 数值。

### 状态策略

| 状态 | 处理方式 |
|---|---|
| 加载中 | 申请列表、申请详情和写操作分别局部加载，保持壳层稳定，不使用全屏遮罩或骨架屏。 |
| 空状态 | 列表显示与当前筛选对应的“暂无……”文案；未选择记录时详情区提示选择一条申请，不增加插画。 |
| 错误 | 保留当前已加载数据，在相关区域显示明确原因；写入失败不得伪装成功，日志类型提取主结果不因知识副作用失败。 |
| 禁用 | 提交、批准、拒绝和删除执行期间锁定相关输入与按钮，防止重复请求；完成或失败后恢复。 |
| 申请不符合条件 | 不显示“申请加入知识库”按钮；结果正文仍正常展示，不影响其他现有操作。 |
| 数据过期 | 提交或审核前重新检查主数据、结果和申请状态；发现变化时停止写入并刷新当前状态。 |
| 数据库不可用 | 普通用户当前分析继续完成，但申请明确失败；审核台显示数据库错误且禁用写操作。 |
| 令牌无效 | 审核台拒绝访问，不返回记录数量、结构、配方或原文。 |

## 实现决策

### 日志知识状态模型

日志知识申请只有“待审核”“已批准”“已拒绝”三种状态。所有用户可以提交申请，只有管理者可以改变审核状态；待审核和已拒绝记录永不参与候选检索。拒绝必须记录理由。批准知识若需退出检索，先改为已拒绝再按清理规则处理，不提供绕过审计的直接删除。

### SQLite 单一事实源

继续使用 SQLite，但移除日志知识对 NumPy embedding 与独立 JSON metadata sidecar 的运行时依赖。申请主表保存配方版本、结构 hash、结构 token JSON、日志格式、格式规格 JSON、选择模式、分类特征字段、提取器类型、提取器规格 JSON、审核状态、提交与审核信息、命中统计和替代关系；样例表按申请外键保存原文与内容 hash。时间统一保存为 UTC ISO 8601 文本，JSON 使用 UTF-8、稳定键序和非 ASCII 原文。

### 结构签名与候选排序

结构签名按格式生成：JSON/KV 使用规范化字段路径、键和分隔结构；Header/自由文本使用带位置的固定 token，并把时间、IP、UUID、普通数字等变量替换为占位符。精确阶段比较 canonical token 的 SHA-256；模糊阶段只在相同日志格式、配方版本和选择模式内，以结构 token 集合 Jaccard 或位置化固定 token 比例排序并取最多 3 个候选。首版不设置“相似即命中”的业务阈值，不引入向量数据库、ANN 或新依赖。

### 确定性配方回放

候选只有在当前主数据上通过全部硬校验才算命中：配方版本兼容；字段路径存在或正则可编译；捕获组满足契约；提取值非空；覆盖率满足现有分类策略；完整聚合可以基于当前原始日志重新生成日志类型、数量、覆盖信息和真实样例。相似度只决定校验顺序，任一校验失败继续下一个候选；全部失败后只执行一次现有完整日志类型提取。

### 日志知识申请准入

只有当前日志类型提取完整成功、至少存在 3 条可回放的真实有效原始日志、配方可执行、覆盖率达标、样例血缘有效且当前主数据未变化时，用户才能提交申请。模型自报置信度和相似度分数不属于准入条件。自动探测与显式指定分类特征字段分别记录选择模式；显式模式申请以指定字段参与身份和候选过滤。

### 日志知识申请幂等

申请身份由配方版本、结构 hash、选择模式、显式分类特征字段和规范化提取器规格共同确定。完全相同的待审核申请重复提交返回原申请编号，并补充去重样例但不新增记录；完全相同的批准知识直接提示已存在。已拒绝记录不阻止携带新证据重新申请，新申请保留独立审核身份和历史。

### 审核与原子替代

同一结构在同一选择模式下最多存在一份已批准知识。批准普通申请时再次在保存样例上回放；验证失败保持待审核。批准竞争申请时必须填写理由，并在单个事务内将旧批准记录改为已拒绝、记录被替代关系，再批准新记录；并发批准必须受唯一约束与事务保护，不能出现两个生效版本。普通批准理由可选，拒绝和替代理由必填。

### 日志解析接入顺序

日志类型提取公共入口保持参数与返回结构兼容。处理顺序调整为：生成当前结构查询；检索已批准候选；依次回放；命中则确定性聚合当前事实；未命中则进入现有模型流程。模型流程成功只产生可申请配方，不再自动写为已批准知识。Header 和通用分类路径必须收敛为一次统一知识接入，移除重复直接存储。

### 类型化申请提交

普通用户按钮生成自包含的类型化知识申请步骤，经现有确定性按钮、执行器和适配器链路执行，不让 Planner 从自然语言猜测申请意图。步骤只引用当前日志分类与主数据身份；执行器再次验证准入和数据新鲜度，适配器负责事务提交和稳定结果。第一版不支持自然语言提交、批准或拒绝。

### 本机审核服务

管理审核台使用标准库提供的小型服务端 HTML 应用，绑定 `127.0.0.1`，端口可配置或由系统分配。每次启动以加密安全随机数生成内存令牌，所有读取与写入请求均校验令牌，写操作只接受 POST；令牌不写入数据库、配置或日志。页面输出必须 HTML 转义原文、正则、说明和理由，限制请求体大小，并对敏感响应设置禁止缓存。管理操作直接调用应用服务，不经过普通用户 Planner。

### 数据库路径与部署边界

公共日志知识库在产品语义上属于部署范围内全体用户共享的数据，不属于 SessionState。第一版默认使用现有本地数据库位置，并允许用单一环境配置覆盖到持久化目录；同一服务进程的所有用户共享。多服务器、多容器之间的同步不在本期，禁止把 SQLite 放在不保证锁语义的共享网络文件系统上。

### 原始日志保留与清理

每份申请最多保存 10 条按内容 hash 去重的原始日志，不保存整个上传文件。待审核、已批准和已拒绝记录均默认保留样例；原文不参与相似度、不展示给普通用户、不因命中发送给模型、不进入运行日志。第一版不增加定时清理；管理者可以删除已拒绝记录并级联删除样例。批准记录必须先拒绝后才能清理。

### 旧知识迁移

数据库初始化执行幂等 schema 迁移。旧记录不得自动成为已批准知识：能从既有 metadata 与样例重建声明式配方并通过回放的记录迁为待审核；无法重建或无法验证的记录保留诊断信息但标为已拒绝，并记录稳定迁移原因。旧 embedding sidecar 不重建、不读取，也不作为迁移成功条件。

### 安全与可观测性

记录候选数量、候选 ID、结构相似度、命中或未命中原因、回退次数、申请 ID、状态转换和审核操作者的操作系统账号；禁止记录原始日志、完整正则输入、临时令牌或其他敏感值。管理者账号字段只用于审计，真正授权来自本机回环监听、启动令牌和部署机器访问权限。日志知识存储与审核失败是非致命副作用，不覆盖当前用户已经成功的分类结果。

### 依赖与公共契约

本能力依赖完整、确定性的日志类型枚举和真实样例血缘，因此实现应在 #190 与 #191 的相关契约稳定后接入。沿用 ADR-0005 的类型化按钮与执行器边界、ADR-0009 的 Application 与 Adapter 单向依赖；公共日志知识不属于 ADR-0006 的会话产物。第一版只使用 Python 标准库与仓库已有依赖，无新增模型池、向量库、ORM、账号系统或跨进程同步。

## 测试决策

### 日志分类公共 seam / 已批准知识命中

从最高层 `classify_log_features_headless` 驱动真实结构生成、候选查询、配方回放和当前事实聚合，以临时 SQLite 和可计数模型假件验证：相同结构但变量值不同可以命中；JSON/KV 键顺序变化不影响 canonical 结构；命中时格式/字段/正则发现类模型调用为 0；日志类型、数量、覆盖率和样例全部来自当前输入。

### 日志分类公共 seam / 候选拒绝与单次回退

构造结构相似但字段路径缺失、正则失效、捕获组错误、覆盖率不足和结果为空的候选，断言候选不会成为命中；全部候选失败时完整模型流程恰好执行一次。空数据库、旧 schema、损坏数据库和存储异常均保持现有分类主结果与稳定失败策略。

### 结构检索 seam / 精确与模糊候选

以格式化真实样本验证变量遮蔽、结构 hash 稳定、JSON/KV 路径规范化、Header 位置 token、格式与选择模式分桶、Top-3 顺序和确定性同分裁决。测试只断言候选排序与边界，不把具体内部类或函数结构写死。

### 类型化申请 seam / 准入与幂等

经现有确定性按钮到 PlanExecutor 的最高链路验证：少于 3 条有效日志、失败结果、过期主数据、覆盖率不足和无真实样例血缘时不能提交；合格结果创建待审核申请；重复提交返回同一编号；已批准相同知识不重复创建；失败不改变当前日志分类。

### 知识仓储 seam / 状态与原始日志

使用临时 SQLite 验证三状态约束、只有已批准可检索、每份申请最多 10 条去重样例、拒绝理由必填、批准与拒绝时间和操作者可审计、删除已拒绝记录级联清理样例、批准记录不能直接删除。断言原文不会出现在检索返回、普通用户结果或日志捕获中。

### 审核事务 seam / 竞争配方原子替代

构造同结构同模式的批准知识与两个竞争申请，验证批准新申请在一个事务中拒绝旧记录并记录替代关系；并发审批最多产生一个批准版本。回放失败、事务异常或唯一约束冲突时完整回滚，原批准知识保持可用。

### 本机审核 HTTP seam / 访问控制与页面状态

在随机回环端口启动真实管理 HTTP seam：无令牌、错误令牌和非回环绑定请求不能读取数据；正确令牌可以查看列表和 HTML 转义后的详情；写操作只接受 POST；拒绝缺理由、替代缺理由、超大请求体和重复提交被拒绝。覆盖列表、详情、空、加载、错误、批准、拒绝、替代和删除状态，不断言非关键 HTML 排版细节。

### 选择模式 seam / 自动与显式隔离

同一日志结构分别保存自动探测和显式分类特征字段申请，验证自动请求只检索自动知识，显式请求只检索同一字段知识；显式知识不能改变其他用户的自动探测选择。显式字段变化时视为不同候选身份。

### 旧数据库迁移 seam / 未审核历史安全

从当前旧 schema 快照构造迁移数据库，验证迁移幂等、原始样例保留、可重建记录进入待审核、不可重建记录进入已拒绝、任何旧记录都不会自动成为已批准，且缺失 embedding sidecar 不影响迁移和启动。

### 全量回归 seam / pytest

新增测试继续遵守仓库离线假件策略，不调用真实模型或外部网络。实现完成后全量 `pytest` 必须通过；若修改生产 Python，还需先重新生成架构源码快照并通过文档架构门禁。

## 范围外

- 不建设普通用户账号、管理员账号、密码、OAuth、角色表或公网管理登录。
- 不让管理审核台监听公网或局域网地址；远程部署后的直接管理入口另行设计。
- 不实现多服务器、多容器知识同步、分布式锁或跨进程缓存一致性。
- 不引入 embedding、向量数据库、ANN、Drain3/GPTCache 运行时依赖或新的模型调用。
- 不支持自然语言提交、批准、拒绝或删除知识；第一版用户提交只走结果按钮。
- 不自动批准、不按相似度自动公开、不把用户继续下一步或下载规则视为隐式确认。
- 不实现投票、评分、普通用户撤销公共知识、自动封禁或审核推荐模型。
- 不实现批量审核、全局搜索、原文默认搜索、正则搜索、拼音搜索或语义搜索；未来搜索优先从 ID、hash、格式、分类特征字段、提取器规格、提交说明和审核理由的 SQLite 文本匹配开始，原文搜索需管理者显式开启。
- 不自动过期或定时清理原始日志；第一版由管理者手动清理已拒绝记录。
- 不持久化或复用历史日志类型、计数、覆盖率和样例作为新主数据事实。
- 不改造现有日志类型提取之外的字段映射、枚举提取、威胁类型映射或解析规则导出语义。

## 补充说明

- 本 PRD 使用 `CONTEXT.md` 中“日志解析知识”“公共日志知识库”“日志知识申请”“分类特征字段”和“主数据”等术语。
- UI 模式：`spec-driven`；共两个运行端、4 个页面清单项，其中每端各含 1 个 `app-shell`。实际新增功能承载界面为一页式本机审核台；Chainlit 只增加现有分类结果操作。
- 4 个页面清单项均已有完整 UI 设计描述，无需 PNG；第一版无待扩展 `DESIGN.md` §5 原语。
- 关联研究：Drain/Drain3 的结构化模板匹配适合作为候选检索参考；GPTCache 的两阶段缓存只参考“候选 + evaluator”边界，不采用其 embedding 路线。
- 依赖：#190“以全量正则捕获完整枚举日志类型”、#191“阻止日志类型与真实样本血缘伪造”。依赖未满足时不得让知识命中绕过其正确性门禁。
- 本设计以 SQLite 单一事实源和标准库管理服务为当前最小可用方案；真正出现多实例部署或公网管理需求时，再以独立 PRD 评估集中数据库和身份权限系统。
