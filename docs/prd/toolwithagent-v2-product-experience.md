# ToolWithAgent V2 产品体验与可观测性规格

> 状态：已确认的产品基线
> 日期：2026-09-20
> 范围：普通用户工作台、字段映射编辑、字段调整预览、执行详情、Developer Run 详情、Admin 管理入口
> 视觉基线：以 `docs/design/DESIGN.md` 和现有交互原型为准；本文只规定页面能力与业务行为

## 1. 产品定位

ToolWithAgent V2 是面向日志规则生产的 Agent 工作台，不是普通聊天机器人，也不是通用 Agent 平台。

用户可以从字段映射、字段调整、枚举填充、日志解析或规则导出中的任一任务开始。任务先后顺序由输入数据、已有产物与用户意图共同决定，不使用固定向导。Agent 负责规划和执行；界面负责让用户看懂当前任务、处理必要确认、检查结果并继续工作。

首版不引入 Workspace、通用流程编排器、Terminal、Skill 商店、复杂 Artifact DAG 或成本大屏。

## 2. 角色与信息架构

### 2.1 普通用户

普通用户围绕自己的会话完成业务。主导航只保留：

- 工作台：对话、上传、当前任务、结果与人工确认；
- 任务：查看本人任务及等待处理事项；
- 运行记录：查看本人历史 Run 的业务摘要；
- 用户信息：固定在左侧栏底部。

在首版没有明确的个人可配置项之前，不展示空的“Agent 配置”页面。系统级 Provider、模型和密钥属于 Admin。

### 2.2 Developer

Developer 使用独立的 Run 详情页排查问题。该角色只读，可以查看所有 Run 的诊断数据、复制标识和下载诊断包，但不能替用户重试、取消任务或修改正式产物。

### 2.3 Admin

Admin 包含 Developer 的诊断能力，额外拥有：

- 系统状态；
- 运行记录；
- 用户与角色；
- Provider 与模型；
- 审计记录。

Admin 可以取消排队任务，或填写原因后强制停止异常运行。首版不提供标准字段表、业务 Prompt、用户产物的在线编辑，也不提供 Worker/服务重启按钮。

### 2.4 开发阶段入口

开发阶段可使用明显标注的角色切换器模拟 User、Developer、Admin，不先建设完整登录。角色切换只简化身份入口，不放宽权限；正式认证与会话方案作为独立需求处理。

## 3. 普通用户工作台

### 3.1 页面骨架

- 左侧：产品标识、新会话、主导航、最近会话、当前用户；
- 中间：会话标题、业务消息、当前任务与结果；
- 底部：固定 Composer，支持文本、文件上传、发送与执行中停止；
- 右侧：默认关闭的上下文抽屉，按需显示执行详情或产物详情；
- 右上角：浅色/深色切换，默认浅色并记忆本机选择。

执行详情、Artifact 版本和依赖关系不得常驻挤压主对话区。右侧抽屉同一时间只承载一种上下文，用户可关闭后恢复完整工作区宽度。

### 3.2 对话不是纯聊天

主区只呈现业务上需要理解的内容：

- Agent 对用户意图的简短复述；
- 当前任务及进度摘要；
- 等待用户确认的事项；
- 结果摘要、警告和正式产物；
- 继续操作建议。

模型、Provider、Token、Tool Call、原始请求响应和完整日志不常驻主区。界面使用“执行详情”“判断依据”“输入与输出”，不展示或声称展示模型原始思维链。

### 3.3 当前任务提示

Composer 上方保留一条紧凑提示：

- 运行时显示当前任务和停止入口；
- 等待确认时显示待处理事项并可定位到确认内容；
- 失败时显示原因摘要与重新执行入口；
- 没有进行中事项时不占位。

待处理事项、草稿与队列状态必须持久化，刷新页面或重启 V2 服务后仍能恢复。

### 3.4 多种任务顺序

同一会话可先上传日志做字段映射并导出，再上传 Base64 规则与枚举 Excel 继续填充，也可以直接提出添加、删除或修改字段。系统根据当前输入与产物创建新任务，不要求新建会话。

若存在多个兼容输入且无法唯一判断，Agent 必须询问使用哪一个；不得静默使用“最近文件”。

## 4. 字段映射结果编辑器

### 4.1 打开方式

用户点击字段映射结果的“查看结果”后，中间区域切换为完整表格编辑器；左侧会话导航和底部 Composer 保留。编辑完成后自动回到对话，Agent 从新产物继续。

### 4.2 子规则与分页

- 多个子规则使用类似 Excel Sheet 的横向 Tab；
- 主表不增加冗余的“子规则”列；
- Tab 支持横向滚动，并提供“全部子规则”查找；
- 每页 50 个字段；搜索与筛选作用于整个子规则，不限当前页。

### 4.3 表格字段

| 列 | 规则 |
|---|---|
| 原始字段 | 来自上传数据，用户不可改名 |
| 数据样例 | 源数据中按原顺序出现的前三个去重非空值；可查看更多，最多 20 个并显示行号 |
| 映射的标准字段 | 下拉框，只能选择 TXT 标准字段表中已有的中文名，不允许自由输入 |
| 匹配度 | 自动映射的相似度或证据提示，不得称为校准置信度 |
| 状态 | 映射成功、未匹配或解析异常 |
| 操作 | “取消映射”，只清除关系，不删除原始字段 |

同一子规则内，一个标准字段不能被两个原始字段同时占用。用户选择已占用目标时，界面明确提示替换；确认后原占用字段转为未映射。

### 4.4 分组与排序

默认分组顺序：映射成功、未匹配、解析异常（存在时才显示）。

“映射成功”内按以下顺序：

1. 本次用户已修改；
2. 其余自动映射按匹配度从高到低；
3. 证据不足或存在歧义的行使用橙色提醒。

前端不得自行硬编码“低匹配度阈值”。提醒由后端依据候选差距、证据完整性、确定性校验等结果给出。用户手动选择后不再显示原模型分数，改为“用户选择”。编辑过程中不跳动排序，正式应用或重新打开后再排序。

### 4.5 未匹配与校验

不是所有字段都必须映射。存在未匹配字段时提醒但不拦截保存；解析异常单独展示。平台固定字段及黑名单仍由后端校验，界面不能通过下拉选择绕过。

若“威胁类型”被映射为“其他”或没有找到合适字段，Agent 可以按有界恢复策略再校验一次候选字段；这是受约束的自主恢复，不是无限尝试。

### 4.6 跨子规则相同字段

只把原始字段名或字段路径完全相同视为相同字段，不做模糊匹配。用户修改一处时，如其他子规则也包含该字段，提示是否一并修改，并列出各子规则当前映射与样例：

- 默认只改当前子规则；
- 用户可显式选择其他无冲突子规则；
- 有目标占用冲突的子规则不可选择；
- 多个子规则的已选修改一次性原子提交。

### 4.7 草稿与提交

- 所有编辑先形成草稿并自动保存；
- 刷新页面或重启服务后草稿仍存在；
- 草稿不影响正式规则，也不供 Agent 后续任务使用；
- “应用修改并继续”统一校验并保存全部修改；
- 任一修改失败时全部不应用，保留草稿并定位错误；
- 成功后生成新的不可变产物版本，返回对话并继续后续任务。

有草稿时发送新对话指令，必须先选择：应用后发送、丢弃后发送、返回编辑。

## 5. 字段调整与 Skill 结果预览

普通用户看到的是业务变更，不是内部 Skill 名称或裸 Tool Call。

### 5.1 展示层级

- 对话：一句结果摘要和“查看变更”；
- 中间预览：按子规则 Tab 展示添加、修改、删除；
- 右侧执行详情：展示 Skill 执行时间线；
- Tool Call：默认折叠，仅 Developer/Admin 深入查看。

### 5.2 字段变更组

- 最小选择单位是字段变更组；
- 同一字段的关联操作不可拆开取消；
- 不同字段默认可分别选择；
- Skill 可声明跨字段依赖并把它们组成一个原子组；
- 用户选中的全部组一次性原子提交，任一校验失败则全部不应用；
- 未选择组记为“用户未应用”，本次 Run 跳过，Agent 按最终范围重新规划后续任务，不无限保留为待办。

明确的单字段、非删除变更可直接执行并提供撤销；多组、删除、推断目标、跨子规则或目标有歧义时必须先预览确认。

### 5.3 删除与撤销

选中内容包含删除时只做一次统一二次确认，列出删除字段和下游影响，不为每个字段重复弹窗。

成功后提供“撤销本次变更”。撤销针对本次提交的整个版本，生成新的恢复版本而不是删除历史；受影响的下游产物标记过期并重新执行。若只想改回单个字段，用户再次编辑即可。

## 6. 任务、Run 与失败行为

### 6.1 状态

任务状态为：排队中、运行中、等待用户确认、成功、失败、取消中、已取消。

字段映射中存在正常未匹配字段仍可成功。模型超时、结构化输出错误或确定性校验失败会让整个任务失败，不发布部分正式结果。

### 6.2 重试

- 模型超时或结构化输出错误自动重试一次；
- 正则生成错误按现有实现进行一次修复重试；
- 确定性校验仍失败则结束任务；
- 不允许无限重试；
- 用户点击“重新执行”会以完全相同的输入产物和参数创建新 Run，失败 Run 保留。

### 6.3 取消

用户取消自己的运行需要确认。确认后进入“取消中”，不发布当前部分结果；迟到的模型响应丢弃，既有成功版本不受影响。

### 6.4 产物版本

- 只有成功任务产生可下载的正式产物；
- 失败批次可以保留为诊断证据，但不是业务 Artifact；
- 上游修改后，受影响的下游产物标记为过期，不删除旧版本；
- 普通用户看到简明影响提示，不展示复杂依赖图。

## 7. 右侧执行详情

抽屉默认关闭。普通用户默认看到业务层级：

```text
Run → Task → Skill → Tool Call
```

一对一的 Task 与 Skill 在视觉上可合并，减少层级。内容包括：

- 已完成、当前、等待、失败和未执行步骤；
- 耗时与简短结果；
- 判断依据或验证结论；
- 可展开的输入与输出；
- Tool Call 默认折叠。

点击结果文件时复用同一抽屉展示产物预览、下载、版本和来源，不再额外打开常驻 Artifact 栏。

## 8. Developer Run 详情页

Developer Run 详情使用独立完整页面，Tab 为：

```text
概览 | 执行时间线 | 输入与输出 | 日志 | 产物
```

### 8.1 概览

按顺序展示：故障结论、影响范围、关键证据、建议处理。确定性错误码和校验事实优先；推测必须标注“可能原因”，并链接到相应时间线、调用或日志。成功 Run 显示执行摘要而非故障卡。

### 8.2 执行时间线

左侧为 Run/Task/Skill/Tool 树，右侧为选中节点详情。默认选择失败节点、当前节点或最后完成节点。未执行的下游节点保持灰色，并说明未执行原因。

### 8.3 输入与输出

左侧按时间列调用，右侧显示请求与响应，可切换格式化/原始 JSON。失败调用默认选中；首次调用和自动重试相邻展示。

每次调用至少记录：Run/Task/Skill/Tool ID、模型、Provider、请求 ID、Prompt 版本、标准字段表版本、参数、开始/结束时间、耗时、重试序号、输入产物版本、结果摘要和错误码。

### 8.4 日志

只展示当前 Run，支持按级别、范围、来源和关键字筛选。默认优先错误和警告，可从根因定位到前后文。日志使用结构化字段，至少包含 run、task、skill、tool、request、error 与 duration 标识。

### 8.5 产物与诊断包

产物页用列表和来源关系展示当前、历史、过期、用户草稿及生成失败状态，不上复杂 DAG。诊断包包含 Run 摘要、时间线、调用、日志和产物元数据；默认不包含完整上传文件。

原始业务数据在开发阶段对 Developer/Admin 放开，但 API Key、Authorization、Cookie 等凭据永远脱敏。大内容按需加载，不得写到浏览器控制台。

## 9. Admin 页面

### 9.1 系统状态

首页只展示可操作信息：服务健康、当前运行、排队数量和异常提醒。V2 默认一个 Worker、一次只处理一个模型任务，其余持久化 FIFO 排队；不提供手动调序。

### 9.2 运行管理

Admin 可以查看全部 Run，取消排队任务，或强制停止异常运行。强制停止必须填写原因并写入审计；停止不删除旧成功版本，也不保留当前部分结果。

### 9.3 Provider 与模型

配置变更只影响新 Run，不改变进行中运行。密钥只能重新输入，不能明文回显。测试连接是独立的配置检查，不创建业务任务。

### 9.4 用户与角色

角色变更从用户的下一次请求生效，不中断正在运行的 Run。Admin 可查看所有诊断信息，但不能直接修改用户正式产物。

### 9.5 审计

所有管理动作记录操作者、时间、动作、目标、变更前后值和原因。敏感值只记录是否变化，不记录明文。

## 10. 可排障数据基线

为了排查字段映射错误、模型响应超时、自动重试失败和产物异常，系统必须关联保存：

- 会话、任务、Run、Skill、Tool Call、请求与 Artifact 的稳定 ID；
- 输入文件名、大小、类型、哈希、解析结果与选定数据版本；
- 子规则、原始字段路径、候选标准字段、匹配证据、校验结论和用户修改；
- Provider、模型、参数、Prompt 版本、标准字段表版本和请求 ID；
- 每次调用的时间、耗时、重试原因、错误类型、结构化错误码和截断信息；
- 任务状态转换、人工确认、草稿应用、取消、强制停止与管理员操作；
- 正式产物版本、来源版本、过期原因和下载记录。

仅有“最终失败”或一段自由文本日志不足以排障。上述数据需要能从一个 Run 互相跳转，并遵守凭据永久脱敏、业务原文按角色查看的规则。

## 11. 首版验收场景

1. 上传 Excel 完成字段映射并导出规则。
2. 上传 Excel，映射后手动调整字段、填充枚举并导出。
3. 在同一会话先完成映射，之后上传 Base64 规则和枚举 Excel 继续处理。
4. 威胁类型得到“其他”时自动复核一次，并正确记录证据与重试。
5. 映射结果按成功/未匹配/异常分组，50 条分页，全量搜索有效。
6. 标准字段下拉只出现标准表中文名，重复占用触发替换确认。
7. 多子规则相同原始字段提示可选联动，默认只改当前子规则，冲突项不可选。
8. 草稿跨刷新和服务重启恢复；未应用草稿不会影响 Agent 后续输入。
9. 多字段 Skill 允许按字段变更组选择；同一字段关联操作不可拆分。
10. 删除统一二次确认；提交失败原子回滚；撤销产生新版本。
11. 模型超时或结构错误只自动重试一次，最终失败不发布部分 Artifact。
12. 用户重新执行创建新 Run 并固定复用原输入；旧失败 Run 可诊断。
13. 取消中的迟到响应不会提交结果；Admin 强停需要原因并产生审计。
14. 待确认事项在刷新和服务重启后仍存在。
15. 普通用户右侧抽屉默认关闭；Developer Run 详情可完整定位到失败调用和关联日志。
16. User、Developer、Admin 权限互相隔离，API 密钥在所有界面和诊断包中均不回显。
17. 浅色为默认主题，切换深色后刷新仍保留，两个主题下状态不只依赖颜色表达。
18. 使用同一组脱敏真实样本对 Chainlit 与 V2 执行双入口兼容验收，下载命名和规则导入结果一致。

## 12. 延后事项

- 枚举手工编辑器：依赖 Issue #189 自动枚举能力进入主任务后再设计；
- 完整认证、单点登录和细粒度原文权限；
- 多 Worker、队列优先级和跨入口统一调度；
- 动画、微交互和最终品牌视觉打磨；
- 复杂 Artifact DAG、在线 Prompt/标准字段编辑和自定义仪表盘。

这些延后项不得成为首版会话、任务、Run、草稿和产物数据模型中的隐式前提。
