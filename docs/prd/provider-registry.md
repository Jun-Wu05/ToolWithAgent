# PRD：多提供商接入——提供商注册表与智谱、OpenAI、OpenRouter 扩展

## 问题陈述

系统目前仅接入 DeepSeek 与硅基流动两家 LLM 提供商，且提供商分支散落在六个消费点（模型构造、日志解析直连链路的端点/密钥/能力判断、模型列表与连接测试、设置界面下拉框三处硬编码）。每新增一家需要同步修改六处。同时存在三类已确认的一致性缺陷：直连链路的端点与密钥懒加载后不再更新、且用 import 时类属性快照判断提供商，运行时切换后判断不随切换生效；密钥缺失行为各家不一致（Team 构造对 DeepSeek 抛错、对硅基流动仅告警，UI 保存只校验 DeepSeek）；Team 只在设置界面保存后创建，`.env` 配置完整的用户不碰设置界面则所有消息被「Team未初始化」拒绝，与 ModelConfig「环境变量优先、界面为会话级覆盖」的设计意图矛盾。

## 解决方案

引入提供商注册表：每家提供商的全部接入参数收敛为单点声明的 ProviderSpec 条目，六个消费点全部改为查表（ADR-0007）。现有两家迁移进注册表且行为不变；以纯声明方式接入智谱、OpenAI、OpenRouter 三家。修复上述三类缺陷：直连链路随运行时切换刷新端点与能力；密钥缺失统一为「构造时抛出带具体变量名的错误 + UI 按最终解析结果校验」；Team 改为懒初始化，恢复 .env 优先语义。聊天密钥与嵌入向量密钥两套独立解析，互不影响。提供商相关文件合并提升内聚：注册表并入 model_config（不新增文件）、model_manager 并入 settings_handler（净删一个文件）、设置控件构建归入设置模块。

## 用户故事

US-1：作为规则配置操作者，我想在 `.env` 配置任一已接入提供商的密钥后直接使用系统，不必在设置界面重复配置，以便部署配置与交互界面各司其职。

US-2：作为规则配置操作者，我想在设置界面看到全部已接入提供商（DeepSeek、硅基流动、智谱、OpenAI、OpenRouter），选择任一家后能拉取其模型列表并通过连接测试，以便会话内临时切换。

US-3：作为规则配置操作者，我想让运行时切换对两条链路（Agent 模型构造与日志解析直连）同时生效，以便设置界面显示的提供商就是实际请求的提供商，不存在半接入状态。

US-4：作为规则配置操作者，我想在密钥缺失时当场得到明确提示（应设置的变量名或去界面填写），以便配置错误不拖延到调用时刻才暴露。

US-5：作为规则配置操作者，我想让各提供商的 JSON 结构化输出能力按声明启用，不支持的模型场景自动降级为提示词约束，以便个别模型差异不会让请求报错。

US-6：作为维护者，我想通过新增一条 ProviderSpec 声明接入新提供商（消费点零改动），以便接入成本不随提供商数量增长。

US-7：作为维护者，我想让现有 DeepSeek 与硅基流动的全部行为在迁移后完全不变（由全量回归锁定），以便重构不引入回归。

## 实现决策

### ProviderSpec 注册表

在模型配置模块内单点声明每家提供商的接入参数：agno 模型构造类与参数、密钥环境变量名、直连 chat/completions 端点、JSON 结构化输出能力（json_object）、模型列表端点与静态默认模型表、连接测试参数。消费点只经注册表公开查询接口取值，不感知条目内部结构。首版五家：DeepSeek、硅基流动、智谱（OpenAILike，OpenAI 兼容端点）、OpenAI、OpenRouter（聚合端点）。

### 六消费点查表改造

模型构造（原 `_build_model` if/else）、直连链路（原 URL/key/能力三处硬编码）、模型列表与连接测试（原 per-provider 分支）、设置界面供应商下拉框（原三处硬编码 values）全部改为查注册表；Team 构造的 per-provider 密钥分支删除，统一行为。

### 直连链路缺陷修复

直连端点与密钥不再「懒加载一次永久缓存」，改为按当前提供商每次解析（运行时切换后 URL、密钥、response_format 能力全部随切换刷新）；response_format 判断改用运行时提供商查询而非类属性快照；DeepSeek 直连端点尊重其 BASE_URL 环境变量。

### 密钥统一与 .env 优先

密钥缺失统一 fail-fast：构造模型时抛出带具体变量名的错误（如「请设置环境变量 ZHIPU_API_KEY」）；UI 保存设置时按最终解析结果（运行时输入或环境变量）校验非空，`.env` 已配的用户切换提供商不被要求重填。聊天密钥链收敛为「当前家环境变量 → FALLBACK_API_KEY」，删除跨家误用的硅基流动环节；嵌入向量密钥独立固定硅基流动，与聊天提供商无关。Team 懒初始化：消息到达时若 Team 未创建且配置可解析则自动创建，解析不出密钥时明确提示应设置的变量；设置界面回归「可选的会话级覆盖」。

### 能力与思考禁用声明

五家 JSON 结构化输出能力全部声明为支持（智谱经官方文档查证已支持 response_format，其静态默认模型表只收录支持结构化输出的模型；个别模型不支持时连接测试或首次调用即暴露，改声明即可）。思考模式禁用列表保持全局模型级，收敛为单点定义（当前两处重复合一）；超时/重试参数不进注册表，维持统一值与调用方传参现状。

### 文件合并与死代码清理

提供商相关文件从七个收敛为五个：注册表并入模型配置模块（不新增文件）；model_manager 并入 settings_handler 后删除该文件（设置全链路：控件、事件、模型列表、连接测试归一）；start_handler 的设置控件构建移入设置模块，仅保留会话初始化与 embedding 后台启动。删除无消费者的 fallback 模型死代码（get_fallback_model / get_model_with_fallback / FALLBACK_MODEL / FALLBACK_ENABLED，保留 FALLBACK_API_KEY）、requirements.txt 重复的 agno 声明、.env.example 无消费者的遗留变量。

## 测试决策

### 注册表单测 seam / 五家规格与密钥解析

断言五家规格查表构造出正确的 agno 模型类与参数（不发起网络）；密钥解析链（运行时 > 当前家环境变量 > FALLBACK_API_KEY）与各家缺失时的报错文案含具体变量名；思考禁用列表单点生效。

### 直连链路 seam / 端点密钥能力与切换刷新

mock httpx 断言：按当前提供商规格发送正确的端点、密钥、response_format；运行时切换提供商后端点与能力随之刷新（缓存缺陷的回归锁）；不支持能力声明时请求不含 response_format。

### 设置界面 seam / 模型列表连接测试与下拉框来源

mock httpx 断言：模型列表按各家的列表端点拉取、失败时静态默认表兜底；连接测试按规格构造请求；供应商下拉框 values 由注册表生成（五家自动出现，新声明自动出现）。

### Team 懒初始化 seam / 环境变量优先与缺密钥提示

环境变量配置完整时消息到达自动创建 Team，不再出现「Team未初始化」拒绝；密钥缺失时返回包含应设置变量名的明确提示。

### 行为不变回归 / 全量测试

现有全量测试套件通过即为两家迁移行为不变的最强锁定；同时执行 `git diff --check`。

## 范围外

- 不修改嵌入向量链路（固定硅基流动，含其密钥解析）。
- 不新增 UI 页面或组件形态（设置界面仅替换数据源与校验口径）。
- 不做按模型粒度的能力声明（依靠默认模型表收录已验证模型兜底）。
- 超时/重试参数不按提供商声明。
- 不做仓库级文件重组（合并仅限提供商相关文件）。

## 补充说明

- UI 模式：headless；不涉及页面、States 矩阵或设计稿。
- 架构决策已由 ADR-0007「提供商注册表」固化；术语「模型提供商 / 提供商规格」已入 CONTEXT.md。
- OpenRouter 为聚合入口，一个密钥可达多家底层模型；其模型列表端点返回体量大，静态默认表只收录代表性模型。
