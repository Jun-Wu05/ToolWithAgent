## 1. Executive Summary

**Problem Statement**：V2 当前把对话、结果、运行轨迹和映射编辑分置在多个 Tab 与抽屉里，用户上传 Excel 后容易失去当前任务和下一步的联系。重复卡片及状态标签增加阅读负担，字段审查又缺少与原对话并存的空间。

**Proposed Solution**：默认以舒展的对话承载任务；文件、进展和待确认动作跟随相关消息。同一会话可切换“对话 / 轨迹”，从消息中的 Run 入口定位并展开轨迹记录。用户需要审查时打开可拉伸、可关闭的右侧资源工作区，以页签查看单实例字段映射和结果。应用成功后，真实结果入口回到对话，工作区继续开放；轨迹视图占用主画布，选中记录详情在画布内查看。

**Success Criteria（正式实现的验收条件）**：

1. 在 1440px 完成“上传 Excel → 查看进展 → 审查映射 → 应用 → 找到结果”闭环；1024px 不丢失关键动作、不出现整页横向滚动。
2. 已上传、执行中、待确认、已完成、失败五个主路径检查点均有明确文字、下一步和可追溯的会话/Run 关联；排队、取消中、已取消按后端真实状态显示，不归并成成功或失败。评审者在每个检查点能于 10 秒内指出当前状态及可执行动作。
3. 1440px 下映射区可拖动中线实时调宽、收起与重开；对话至少保留 360px 可读宽度。关闭再打开后服务端草稿、筛选和待处理冲突不被静默丢弃。应用成功后，对话展示真实结果入口，右侧保持开放。
4. 技术证据可从相关运行记录进入；真实 Skill/Tool 身份显示真实采集值，缺失时显示“未采集”，不以步骤名称代替身份。
5. 用联合验收的同一 Excel、会话和 Run 核对界面状态与后端终态；静态设计图及旧合成原型不能作为业务验收证据。
6. 同一会话的“对话 / 轨迹”切换可定位 Run；轨迹暂时隐藏右侧工作区，返回对话后恢复输入、滚动、页签和宽度。右侧整区收起、标题栏重开、消息入口直达与单页签关闭各有明确行为。

## 2. User Experience & Functionality

**User Personas**：普通用户提交日志或规则文件、审查字段、取得结果；Developer 按既有权限检查 Run、Tool、Skill 与错误证据；Admin 保留既有管理入口。本轮主路径聚焦普通用户，其他角色沿用相同证据层级但不改权限。

**主路径**：上传后的文件行附在对应输入消息附近；Agent 的进展摘要附在对应回复和 Run 上。文件名称、用途和状态留在消息中；Run 入口切到当前会话的轨迹并定位、展开记录。待确认时，回复给出缺口及“打开映射区”；点击后右侧打开单实例映射页签。用户选择字段并沿用现有自动保存、冲突确认与应用流程。服务端确认成功并刷新后，对话出现关联结果与产物入口；点击后在右侧一个“结果 / 产物”页签中选择本次产物和版本，映射页签仍可找回。轨迹视图的选中记录可就地查看步骤和证据。没有消息关联的旧数据保留“历史独立操作”标识，不补造对话消息。

| User Story | Acceptance Criteria |
|---|---|
| As a 普通用户, I want to 上传 Excel 后在对话里看到文件及状态, so that 我知道文件属于哪次任务。 | 文件名、上传用途与所属输入可定位；上传完成只表示文件已接收，不提前宣称业务处理成功。排队、解析、失败各有文字。上传和终态沿用现有接口。 |
| As a 普通用户, I want to 在当前回复看到执行进展, so that 我不用离开对话寻找下一步。 | 进展与对应 Run 关联；待确认、失败、可重试时显示具体动作；历史无关联数据仍明确标记为历史独立操作。 |
| As a 普通用户, I want to 在对话旁审查映射, so that 我能同时看见任务上下文和字段样例。 | 1440px 右侧工作区初始占主内容约 55%，可拖动调整；对话保持至少 360px 可读宽度。1024px 映射区覆盖主内容，关闭后返回对话。表格使用真实字段、样例、状态和现有搜索/筛选。 |
| As a 普通用户, I want to 安全地关闭并重开映射区, so that 我不会丢失修改。 | 可关闭、重新打开；已保存草稿仍在。保存中或冲突确认未完成时遵守现有阻断/确认语义，不把未保存选择当作已保存。关闭后焦点返回触发入口；重新打开后从服务端确认草稿版本。 |
| As a 普通用户, I want to 应用后在对话里取得结果, so that 我能继续这次任务。 | 服务端应用成功后才显示成功与真实产物入口；右侧保持打开。失败或处理中显示对应状态，不生成虚构结果消息。产物可回溯到 Run 与输入。 |
| As a 普通用户, I want to 收起或重新打开右侧工作区, so that 我能临时获得完整对话宽度并继续审查。 | “收起工作区”保留本次会话的页签、选中项与宽度；标题栏“打开工作区”恢复上次页签，消息入口激活目标页签；单页签 `×` 只关闭该页。保存中与冲突未处理时遵守现有阻断/确认语义。 |
| As a Developer, I want to 从运行记录查看证据, so that 我能定位错误或核实调用。 | 对应 Run 可按需展开步骤、错误码、耗时和真实 Skill/Tool 身份；角色限制不变；未采集信息明确标注。 |

**视觉与控件**：默认对话最大工作宽度约 900px，长段正文继续限制阅读行长；右侧编辑区使用更宽的数据排布。中性白、石墨色和少量状态色建立层级，主要按钮使用克制的深青色。采用清晰的中文无衬线字级；不使用装饰性眉题、机械编号、渐变或重复卡片。所有可操作控件有可见焦点和明确禁用、加载、错误状态；拖动分隔线也支持键盘调整。

**Non-Goals**：本轮不新增 Agent 能力、后端 API、数据库字段、角色权限、结果生成逻辑或自动恢复策略；不重做 Admin 管理台；不要求先制作交互原型。管理台普遍变慢问题不在本前端 PRD 中宣称修复；真实上传验收仍按现有验收线处理。

## 3. AI System Requirements (If Applicable)

**Tool Requirements**：只消费现有会话、Run、进展、Artifact、映射草稿及模型调用诊断数据。Skill/Tool 身份仅来自真实采集字段；空值显示“未采集”。界面文案不能凭任务名称、图标、模型回复或演示样例推断发生了某次调用。

**Evaluation Strategy**：取联合验收中的真实 Excel、会话 ID、Run ID、错误码及结果产物，逐一比对前端状态和服务端状态；覆盖身份已采集、未采集、失败与重试。检查展开的执行步骤是否能定位对应输入与产物，且不同角色只看到有权限的信息。

## 4. Technical Specifications

**Architecture Overview**：沿用 React 18、TypeScript、Vite 与 FastAPI 分离架构。`ConversationTimeline` 继续绑定输入、Run 和产物；`MappingWorkspace` 继续负责现有草稿、筛选、冲突和应用行为。`App` 将当前四 Tab 的工作台改为同一会话的“对话 / 轨迹”视图和一个右侧资源工作区；映射与结果在右侧以两个页签切换，映射保持单实例。消息中的 Run 入口切到轨迹、定位并展开记录详情；切到轨迹时隐藏而非销毁右侧工作区，切回后恢复其状态。历史会话与角色入口保持可达。

**Integration Points**：复用 `api.ts` 中的上传、会话刷新、Run 详情、映射视图、草稿创建/保存/应用、下载与诊断接口。工作区宽度只存于当前页面状态，收起后本次页面保留，刷新后恢复默认宽度；草稿状态仍以服务端为准。1440px 下工作区初始占主内容约 55%，分隔线支持指针拖动、方向键逐级调整及明确焦点；内容随宽度换行，宽表局部滚动，不通过缩小字号容纳。映射区 480px 最小宽度仅是待实测建议。在 1024px 及更窄视口，以覆盖主内容的方式打开并提供“返回对话”。现有会话详情包含产物、Run 列表已有分页接口；本轮不新增全局产物搜索 API。

**Security & Privacy**：保持现有认证、角色权限和下载授权；错误摘要不得暴露密钥或完整敏感文件内容。设计图使用演示数据；真实字段样例与诊断信息只从有权限的 API 响应渲染。

**与现有设计基线的冲突及实施前同步项**：本 PRD 规定新的工作台信息架构。实施前修订旧视觉基线和四 Tab 计划中的冲突条目；保留未冲突的角色、权限、状态文字与可访问性要求。旧方案的 #310、#406 按“被新方向取代”记录，不记作旧方案通过验收。

| 当前基线 | 新方向 | 定稿动作 |
|---|---|---|
| 四 Tab 混合工作台将“对话、概览、结果、轨迹”设为并列主入口 | 同一会话保留“对话 / 轨迹”视图；文件状态留在消息中，映射与结果在右侧资源页签，历史从左侧会话入口到达 | 按布局决策记录页签、定位、开合与状态恢复；旧四 Tab 精修计划保留为历史。 |
| 右侧上下文抽屉约 384px、单实例 | 映射编辑需要可拉伸的宽工作区，轨迹详情需要足够阅读宽度 | 右侧使用一个资源工作区；消息 Run 入口在轨迹画布内展开详情。 |
| 旧蓝灰 Token、状态点与统一卡片语言 | 中性白与石墨为主，状态文字优先，减少边框和卡片 | 审阅静态图后更新 `v2-visual-baseline.md` 对应条目；保留语义状态和对比度要求。 |

## 5. Risks & Roadmap

**Phased Rollout**：

1. **集成前置（已完成）**：#423、#424、#426 已合入 V2 开发线；联合回归通过根仓全量 pytest、V2 后端 233 项、前端 214 项、lint 和构建。实施前仍须修订旧视觉基线及四 Tab 计划的冲突条目，并保留真实 Excel、会话和 Run 的验收标识。
2. **对话主路径**：按仓库 Issue SOP 分段实施对话内文件、进展、待确认动作和五个主路径检查点；不改上传及 Run 终态契约。
3. **会话视图与右侧工作区**：保留“对话 / 轨迹”切换及 Run 定位、展开，复用草稿、搜索筛选、冲突确认和原子应用；实现可拖动、可收起的单实例右侧资源工作区及映射、结果两个页签，关闭最后一个页签自动收起；再把服务端成功后的真实产物入口呈现在对应对话中。
4. **证据与验收**：从关联 Run 的轨迹记录按需展开步骤和真实 Skill/Tool 身份，覆盖“未采集”；以同一真实 Excel、会话和 Run 完成 1440px、1024px、键盘、失败、刷新、拖动与开合回归。Admin 与深色主题的进一步调整留待本轮验收后评估。

上述实施任务的 issue、PR 或 spec 正文按仓库规则先全文展示给用户，再发布 tracker。

**Technical Risks**：长会话与大型映射表并存可能增加渲染开销；窄桌面覆盖式工作区需要维持上下文可返回；草稿保存、应用冲突和结果刷新之间可能短暂不同步。实施时以当前分页、草稿令牌和终态契约为准，补齐相应回归测试，并用真实 Excel/Run 做浏览器验收。
