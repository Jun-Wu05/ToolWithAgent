# V2 会话详情性能修复（#425）

## 已定位的问题

`Store.get_conversation` 每次通过 `_conversation_facts` 重建完整业务会话并调用 Planner 事实投影。
即使页面只需要“有无日志”和配置/产物摘要，也会重新解析整份 Excel，并推导页面不返回的字段池。

## 修复与边界

- 只读页面使用 `summary_only=True`：Excel、CSV、NDJSON 读到第一条有效日志即停止；已保存状态中的日志列表只复制一条。
- 页面事实投影使用 `include_field_pools=False`，跳过可用/可映射字段池推导，保留现有摘要字段。
- 业务执行仍默认完整读取；无缓存、迁移、新依赖或前端 API 结构变更。
- 仍根据当前输入与产物重建摘要并校验上传 Blob 的 SHA；不复用过期事实。空日志、缺失列及内容损坏保持失败状态。
- 空文件可能需要扫描完才能确认无有效日志；JSON/编码配置仍需完整解码以识别配置根结构。附件和产物的读取也保留原有完整性校验。

## 同数据计时（2026-10-29）

使用现有人工验收数据中的同一会话，在同一 Python 进程交替比较旧事实构建路径和修复路径，直接调用 `Store.get_conversation`。
旧路径恢复完整会话、调用完整 `build_session_facts`；新路径调用本分支实现。未调用模型、发布产物或修改数据。

| 路径 | 三次耗时（秒） | 中位数（秒） |
|---|---|---|
| 旧路径 | 4.642 / 5.478 / 5.553 | 5.478 |
| 修复路径 | 0.053 / 0.059 / 0.047 | 0.053 |

两条路径返回的全部页面安全摘要字段逐项相等。该结果是本机同数据的后端函数计时，不是浏览器页面加载或生产环境 SLA。
