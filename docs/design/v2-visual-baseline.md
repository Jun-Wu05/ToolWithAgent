# V2 视觉基线规格（现行实现与新体验方向）

> 状态：2026-10-30 新体验方向已确认；下方数值表保留现行 Quiet Precision 实现基线，不能当作新界面的最终色票。
> 新体验规格：[Issue #427](https://github.com/Jun-Wu05/ToolWithAgent/issues/427)；静态方向与两张设计图见[已确认的静态方向](https://github.com/Jun-Wu05/ToolWithAgent/blob/5055cf859fa04ee1082e243e5e579170434496a9/docs/design/v2-experience-static-direction.md)。
> 历史依据：`docs/design/agent-console-suite-analysis.md` §8.4、`docs/prd/v2-visual-refresh.md`（#303 / PR #304）。

## 0. 新体验方向的适用范围

- 普通用户工作台默认呈现约 900px 的舒展对话。文件、真实进展、待确认动作和运行记录留在对应消息附近；历史、概览和完整轨迹保留可到达的次级入口，不再作为四个并列主 Tab 的新界面验收目标。
- 审查字段映射时打开单实例右侧工作区。1440px 初始约占主内容的 55%，可拉伸、可关闭，对话至少保持 360px 可读宽度；1024px 及更窄视口覆盖主内容并提供返回对话。成功应用后，真实结果入口回到对话，工作区保持打开。
- 右侧轻量执行／产物上下文抽屉与映射工作区互斥。关闭和重新打开不得把未保存选择伪装为已保存草稿；草稿版本、冲突和应用终态以服务端为准。
- 新界面以中性白和石墨为主，少量深青色标识主要操作，状态用文字与语义色共同表达；减少重复卡片和装饰标签。两张静态图确认信息层级，不提供精确 OKLCH/HEX 或真实业务验收证据。
- §3 的数值表记录当前已实现的明暗主题。新界面的精确色值须从已确认静态方向形成可核对的 Token 规格后再替换；本文件不从截图推测数值。现有深色切换、角色权限、焦点和状态文字要求继续有效。

## 1. 与 DESIGN.md 的关系

DESIGN.md 保留通用设计系统、角色和可访问性原则。本文件 §0 与 Issue #427 规定新工作台的信息架构；它们与 DESIGN.md 及下方旧布局描述冲突时，以新体验规格为准。§3 的数值表与其余旧组件尺寸仍用于描述当前实现，直到新界面 Token 与组件规格经过确认。

DESIGN.md 继续有效的部分：设计理念（“可信的运维台”）、角色与权限、整体宜忌、焦点可见性、状态文字和不泄露敏感内容的验收要求。旧侧栏宽度、并列 Tab 与固定窄抽屉布局不再约束新工作台。

修改已确认的数值 Token 仍需人工确认，并在 §9 版本日志登记。新布局先按 §0 和 Issue #427 实施，再用真实 Excel、会话与 Run 验收。

## 2. 用色的基本思路

§2–§7 除明确写出“新工作台”的条款外，记录现行界面的视觉与组件规格，供迁移时核对；旧蓝色、并列 Tab、固定窄抽屉及组件落点不构成新界面的验收要求。

### 2.1 分区优先用背景色，其次才是线条

| 做法 | 什么时候用 | 不要用来 |
|---|---|---|
| 背景深浅分层（页面底 → 卡片 → 内嵌底） | 默认手段：页面最底层、内容卡片、日志/代码块的底色 | — |
| 浅色细线（`--border-subtle`） | 表格行与行、列表项之间、区块内部分隔 | 输入框等控件的描边 |
| 控件描边（`--border`，深一档） | 输入框、下拉框、按钮 | 区域分隔（分区靠背景色） |
| 彩色浅底（tint，五种） | 状态提示底色、选中态、悬停、提示条 | 大面积装饰；tint 叠 tint；正文整段放在 tint 上 |

### 2.2 语义色的纪律

- 语义色只表达状态和结果（成功/警告/失败/运行中），不当装饰色用；
- 语义色显示文字时，旁边必须有状态文字（§3.6，照顾色弱用户的硬性要求）；
- 现行实现中的靛蓝、青色只用于图标点缀。新工作台的主操作与辅助色遵循 §0 的中性白、石墨和少量深青色方向；不沿用旧蓝色作为新界面的默认主操作色。

### 2.3 文字分三档

| 档位 | 变量 | 用在哪 | 注意 |
|---|---|---|---|
| 主文字 | `--foreground`（深蓝黑） | 正文、标题、表格主列 | — |
| 说明文字 | `--muted-foreground`（中灰） | 辅助说明、次要信息 | — |
| 辅助文字 | `--faint`（浅灰） | 时间戳、行号、占位符 | 不能用于可交互的文字——按钮、链接、状态字、可点击的行标题都太浅看不见 |

### 2.4 尺寸

- 控件圆角6px，内容边界6–10px，按用户已验收原型的层级使用；
- 阴影只有一档（`--shadow-modal`），只给浮层用（弹窗、抽屉、下拉）；普通卡片不加阴影；
- 现行实现采用 224px 侧栏、56px 顶栏和约 384px 的轻量上下文抽屉；这些数值仅用于当前页面回归。新工作台的映射区尺寸与窄屏行为按 §0，侧栏和顶栏沿用可用的壳层能力，具体新尺寸不由旧原型数值推定。

### 2.5 本轮新增的"要 / 不要"

- 不要在代码里写死颜色绕过变量（新代码零写死；存量在实施时统一换成变量，见 §6）；
- 不要混用两档圆角；
- 不要拿深色的 HEX 值自行换算（一律用 §3 记录的 OKLCH 原值）；
- 不要只给颜色不给状态文字；
- 耗时、Token 数、ID 这类数字列要用 `num` 工具类对齐。

## 3. 颜色变量总表

### 3.1 OKLCH 说明

OKLCH 是一种颜色记法，把亮度、饱和度、色相分开记录，比 HEX 更稳定。对现行 Quiet Precision Token 做回归时，以本表的 OKLCH 为准；表中的 HEX 只是方便快速识别，深色 HEX 为换算近似值（标 ≈）。新界面的颜色验收须待新 Token 数值确认后进行，不从本表 HEX 反算或沿用旧主色。

### 3.5 工具类

```css
.focus-ring:focus-visible{ outline:2px solid color-mix(in oklab,var(--primary) 80%,transparent); outline-offset:1px }
.row-hover{ transition:background 120ms ease }
.row-hover:hover{ background:var(--tint-primary) }
.num{ font-family:var(--font-mono); font-variant-numeric:tabular-nums }
.shadow-modal{ box-shadow:var(--shadow-modal) }
```

`focus-ring`：键盘操作时的焦点框，输入框、按钮、列表行统一使用。`row-hover`：表格行/列表项的悬停效果（120ms 渐变到浅蓝底）。`num`：数字用等宽字体并对齐，耗时列必用。`shadow-modal`：浮层阴影。"运行中"状态点的呼吸动画（pulse-dot）维持延后决议，本轮不做。

### 3.6 状态表达

| 状态 | 现行语义 Token | 屏幕上显示 |
|---|---|---|
| 排队中 | `--faint` | “排队中”及可追溯的 Run |
| 运行中 | `--info` | “运行中”及真实进展 |
| 等待确认 | `--warning` | “等待确认”及具体动作 |
| 已完成 | `--success` | “已完成”及真实结果入口 |
| 失败 | `--danger` | “失败”及原因或可用的重试动作 |

颜色和状态字必须成对出现；实际状态以服务端为准。取消中、已取消等其他既有状态也须显示原状态文字，不归并为成功或失败。现行 Token 的色值见 §3.3/3.4；新界面 Token 定稿前不沿用旧表中曾写入的蓝绿 HEX 作为验收值。

## 4. 组件规格

通用要求：可交互元素键盘聚焦时显示焦点框（`focus-ring`）；状态呈现遵守 §3.6；可点击元素高度不小于 28px。

### 4.1 状态圆点 + 状态字（StatusDot / StatusText）

- 结构：圆点（7×7px）+ 状态字（11px），如 `● 运行中`；
- 颜色按 §3.6 状态 × 主题两套取值；
- 全站通用的最小状态零件：最近会话、任务列表、运行记录、映射编辑器状态列都用它。

### 4.2 任务提示条（TaskHintBar）

- 现行实现位于输入框正上方，宽度与输入框对齐；没有进行中的事项时整条不渲染。新工作台的主路径状态与动作放在对应消息附近；若保留全局提示条，只作定位入口，不重复整段状态内容；
- 三态：运行中 → 浅蓝底（tint-info）；等待确认 → 浅黄底（tint-warning）；失败 → 浅红底（tint-danger）；
- 结构：状态点 + 加粗标题 + 一句说明 + 右侧主色动作链接（如"查看 ›"）；
- 高约 34px，内边距 8×12px，圆角 6px。

### 4.3 右侧上下文抽屉（ContextPanel）

- 现行轻量上下文抽屉同一时间只开执行详情或产物详情之一。新工作台还可打开映射工作区；三者互斥，同一时刻只显示一个右侧面板；
- 结构：头部（标题 + 耗时/Token 元信息 + 关闭按钮）→ 标签页（执行时间线 / 输入与输出）→ 可滚动内容区；
- 关闭后工作区恢复完整宽度；开合动画不超过 250ms，系统开启"减少动画"时禁用；
- 约 384px 的宽度只适用于现行轻量抽屉，不适用于映射工作区。映射区尺寸、关闭重开与 1024px 返回行为按 §0。

### 4.4 工具调用块（ToolCallBlock）

- 收起时一行：展开箭头 + 状态点 + 等宽工具名（如 `semantic_lookup`）+ 右对齐的耗时 / Token（`num`）；
- 展开后：输入、输出各一段等宽代码块（11px / 行高 1.6），之间用细分隔线；
- 底色 `--surface-inset`、描边 `--border-subtle`、圆角 6px；aria-expanded 随折叠状态更新。

### 4.5 输入框区（Composer）

- 附件 chips：胶囊形（999px 圆角），内嵌底色，图标可用辅色点缀，右侧移除钮（悬停呈危险色提示）；
- 焦点态：整个输入区描边转主色，叠加 3px、14% 透明度的主色光环（`color-mix`）；
- 键盘：Enter 发送 / Shift+Enter 换行；发送前存在未应用草稿时先弹出处理选择（行为规格归产品体验 PRD）；
- 底栏：左侧"上传 + 支持的文件类型"（ghost 态），右侧圆形发送钮（30px，主色底 / `--primary-foreground` 箭头）；
- 辅助行：10px 辅助文字色提示（"Enter 发送 · Shift+Enter 换行"）。

### 4.6 快捷入口 chips（工作台空态）

- 形态：6px 圆角小按钮阵列，卡片底色 + 控件描边，悬停转选中浅蓝底；
- 行为：点击仅将内容预填进输入框，不自动发送、不覆盖未发送的草稿；
- 文案只取自已交付能力对应的任务示例。

### 4.7 数字格式（fmtMs / fmtTokens）

- 耗时：无值显示"—"；不足 1 秒显示整数 ms；不足 1 分钟显示一位小数秒；更长用"x 分 x 秒"；
- Token：≥1000 用 k 缩写（如 8.4k）；
- 数值列统一套 `num` 工具类。

## 5. 页面落点速查

| 字段映射编辑器 | 两档线（表格行细分隔线 / 下拉框描边）；状态圆点/字；修改行选中浅蓝底 + 左侧警告指示条；解析异常行危险浅底；输入框细节；右侧抽屉复用 |

## 6. 实现约定（v2/frontend）

- 现行颜色 Token 集中在 `src/styles.css`，工作台布局另有 `src/workbench.css`；新界面继续由语义 Token 承载颜色，不在组件里散落硬编码值。§3.3/3.4 的数值只能验证当前实现，新方向的色值须另行确认；
- 新界面实现时将旧布局中的局部硬编码统一迁入语义 Token；当前表中已实现值只作回归依据，不把旧交互蓝用于新界面定稿；
- 主题切换机制不变：class 切换 + localStorage（`twa-v2-theme`）+ 防闪白，仅替换值表；
