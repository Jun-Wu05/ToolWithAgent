## 2. 用色的基本思路

### 2.1 分区优先用背景色，其次才是线条

| 做法 | 什么时候用 | 不要用来 |
|---|---|---|
| 背景深浅分层（页面底 → 卡片 → 内嵌底） | 默认手段：页面最底层、内容卡片、日志/代码块的底色 | — |
| 浅色细线（`--border-subtle`） | 表格行与行、列表项之间、区块内部分隔 | 输入框等控件的描边 |
| 控件描边（`--border`，深一档） | 输入框、下拉框、按钮 | 区域分隔（分区靠背景色） |
| 彩色浅底（tint，五种） | 状态提示底色、选中态、悬停、提示条 | 大面积装饰；tint 叠 tint；正文整段放在 tint 上 |

### 2.2 语义色的纪律

- 语义色只表达状态和结果（成功/警告/失败/运行中），不当装饰色用；
- 语义色显示文字时，旁边必须有状态文字（§3.6，照顾色弱用户的硬性要求）；
- 辅色 `#6366F1`（靛蓝）和第三色 `#06B6D4`（青）只用于图标点缀（如文件类型图标），不用于文字、链接、按钮。

### 2.3 文字分三档

| 档位 | 变量 | 用在哪 | 注意 |
|---|---|---|---|
| 主文字 | `--foreground`（深蓝黑） | 正文、标题、表格主列 | — |
| 说明文字 | `--muted-foreground`（中灰） | 辅助说明、次要信息 | — |
| 辅助文字 | `--faint`（浅灰） | 时间戳、行号、占位符 | 不能用于可交互的文字——按钮、链接、状态字、可点击的行标题都太浅看不见 |

### 2.4 尺寸

- 控件圆角6px，内容边界6–10px，按用户已验收原型的层级使用；
- 阴影只有一档（`--shadow-modal`），只给浮层用（弹窗、抽屉、下拉）；普通卡片不加阴影；
- 侧栏 224px、顶栏 56px，维持 #263 壳层不变；右侧抽屉 384px 左右（最小 380px、最大屏宽 34%）。

### 2.5 本轮新增的"要 / 不要"

- 不要在代码里写死颜色绕过变量（新代码零写死；存量在实施时统一换成变量，见 §6）；
- 不要混用两档圆角；
- 不要拿深色的 HEX 值自行换算（一律用 §3 记录的 OKLCH 原值）；
- 不要只给颜色不给状态文字；
- 耗时、Token 数、ID 这类数字列要用 `num` 工具类对齐。

## 3. 颜色变量总表

### 3.1 OKLCH 说明

OKLCH 是一种颜色记法，把亮度、饱和度、色相分开记录，比 HEX 更稳定。所有颜色以 OKLCH 为准；表中的 HEX 只是方便快速识别，深色 HEX 为换算近似值（标 ≈）。验收只核对 OKLCH，不要从 HEX 反算，避免误差累积。

### 3.2 基础项

| 项 | 规格 |
|---|---|
| 正文字体 | `system-ui, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`（较原版补充 PingFang SC） |
| 等宽字体 | `ui-monospace, "Cascadia Code", "SF Mono", Consolas, monospace` |
| 正文规格 | 14px，行高 1.5；开启抗锯齿 |
| 圆角 | 6px，全站统一 |
| 阴影 | 浅色 `0 12px 32px rgb(15 23 42 / 0.16)`；深色 `0 12px 32px rgb(0 0 0 / 0.5)`；仅浮层使用 |
| 文字选中色 | 主色 22% 透明度 |
| 滚动条 | 细滚动条，颜色与边线一致 |
| 原生控件跟随主题 | 深色模式下拉框、滚动条等系统控件同步变深（`color-scheme` 联动） |

### 3.5 工具类

```css
.focus-ring:focus-visible{ outline:2px solid color-mix(in oklab,var(--primary) 80%,transparent); outline-offset:1px }
.row-hover{ transition:background 120ms ease }
.row-hover:hover{ background:var(--tint-primary) }
.num{ font-family:var(--font-mono); font-variant-numeric:tabular-nums }
.shadow-modal{ box-shadow:var(--shadow-modal) }
```

`focus-ring`：键盘操作时的焦点框，输入框、按钮、列表行统一使用。`row-hover`：表格行/列表项的悬停效果（120ms 渐变到浅蓝底）。`num`：数字用等宽字体并对齐，耗时列必用。`shadow-modal`：浮层阴影。"运行中"状态点的呼吸动画（pulse-dot）维持延后决议，本轮不做。

### 3.6 状态颜色对照

| 状态 | 用哪个色 | 浅色值 | 深色值 | 屏幕上显示 |
|---|---|---|---|---|
| 运行中 | info | #0284C7 | ≈#46AFEC | 圆点 + "运行中" |
| 已完成 | success | #16A34A | ≈#46C473 | 圆点 + "已完成" |
| 等待确认 | warning | #D97706 | ≈#EBAE42 | 圆点 + "等待确认" |
| 排队中 | faint | #94A3B8 | ≈#6C7582 | 圆点 + "排队中" |
| 失败 | danger | #DC2626 | ≈#F75D59 | 圆点 + "失败" |

颜色和状态字必须成对出现，不能只放一个色点；不新增表外状态。

## 4. 组件规格

通用要求：可交互元素键盘聚焦时显示焦点框（`focus-ring`）；状态呈现遵守 §3.6；可点击元素高度不小于 28px。

### 4.1 状态圆点 + 状态字（StatusDot / StatusText）

- 结构：圆点（7×7px）+ 状态字（11px），如 `● 运行中`；
- 颜色按 §3.6 状态 × 主题两套取值；
- 全站通用的最小状态零件：最近会话、任务列表、运行记录、映射编辑器状态列都用它。

### 4.2 任务提示条（TaskHintBar）

- 位置：输入框正上方，宽度与输入框对齐；没有进行中的事项时整条不渲染；
- 三态：运行中 → 浅蓝底（tint-info）；等待确认 → 浅黄底（tint-warning）；失败 → 浅红底（tint-danger）；
- 结构：状态点 + 加粗标题 + 一句说明 + 右侧主色动作链接（如"查看 ›"）；
- 高约 34px，内边距 8×12px，圆角 6px。

### 4.3 右侧上下文抽屉（ContextPanel）

- 同一时间只开一种上下文：执行详情或产物详情二选一，由类型约束保证：`type PanelState = null | { type: "execution" | "artifact"; id: string }`；
- 结构：头部（标题 + 耗时/Token 元信息 + 关闭按钮）→ 标签页（执行时间线 / 输入与输出）→ 可滚动内容区；
- 关闭后工作区恢复完整宽度；开合动画不超过 250ms，系统开启"减少动画"时禁用；
- 宽 384px 左右（最小 380px / 最大 34vw），头部高度与顶栏一致（56px）。

### 4.4 工具调用块（ToolCallBlock）

- 收起时一行：展开箭头 + 状态点 + 等宽工具名（如 `semantic_lookup`）+ 右对齐的耗时 / Token（`num`）；
- 展开后：输入、输出各一段等宽代码块（11px / 行高 1.6），之间用细分隔线；
- 底色 `--surface-inset`、描边 `--border-subtle`、圆角 6px；aria-expanded 随折叠状态更新。

### 4.5 输入框区（Composer）

- 附件 chips：胶囊形（999px 圆角），内嵌底色，图标可用辅色点缀，右侧移除钮（悬停呈危险色提示）；
- 焦点态：整个输入区描边转主色，叠加 3px、14% 透明度的主色光环（`color-mix`）；
- 键盘：Enter 发送 / Shift+Enter 换行；发送前存在未应用草稿时先弹出处理选择（行为规格归产品体验 PRD）；
- 底栏：左侧"上传 + 支持的文件类型"（ghost 态），右侧圆形发送钮（30px，主色底 / `--primary-foreground` 箭头）；
- 辅助行：10px 辅助文字色提示（"Enter 发送 · Shift+Enter 换行"）。

### 4.6 快捷入口 chips（工作台空态）

- 形态：6px 圆角小按钮阵列，卡片底色 + 控件描边，悬停转选中浅蓝底；
- 行为：点击仅将内容预填进输入框，不自动发送、不覆盖未发送的草稿；
- 文案只取自已交付能力对应的任务示例。

### 4.7 数字格式（fmtMs / fmtTokens）

- 耗时：无值显示"—"；不足 1 秒显示整数 ms；不足 1 分钟显示一位小数秒；更长用"x 分 x 秒"；
- Token：≥1000 用 k 缩写（如 8.4k）；
- 数值列统一套 `num` 工具类。

## 6. 实现约定（v2/frontend）

- 单文件 `src/styles.css`，分区顺序：基础项 → 浅色变量（`:root`）→ 深色变量（`html[data-theme="dark"]`）→ 工具类 → 组件样式；变量名逐字采用 §3.3/3.4 的命名（与 Tailwind 语义习惯一致，为将来引入框架预留迁移路）；
- 存量写死的颜色（交互蓝误用 600、单档 `--line`、散落的 outline/hover）在视觉实施第一步统一换成 §3 变量；此后新代码零写死；
- 主题切换机制不变：class 切换 + localStorage（`twa-v2-theme`）+ 防闪白，仅替换值表；
- 验收自检表格式（每行一个变量，可脚本化核对）：

| 变量名 | 规格 OKLCH（浅色 / 深色） | 代码状态 |
|---|---|---|
| `--primary` | oklch(0.623 0.214 259) / oklch(0.71 0.15 255) | 已实现 L42 / 未实现 |
| （其余变量逐行展开） | | |
