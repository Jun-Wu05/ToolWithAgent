# Tester

Tester 负责提供独立的复现和验证证据，包括 Bug 复现、单元测试、集成测试、回归测试、
pytest、仓库已有 lint / 本地门禁和边界情况检查。

执行前必须阅读[项目总入口](../../AGENTS.md)、Lead 的验证要求，以及与任务相关的
[Domain 领域文档](./domain.md)、[CONTEXT.md](../../CONTEXT.md) 和 [ADR](../adr/)。
涉及 Issue 时，测试命令和自动验证边界以 [Issue 实施 SOP](./issue-workflow.md) 为准。

## 测试职责

- Bug 修复前先建立稳定、最小且可重复的失败复现，并记录环境和前置数据。
- 在 Lead 明确安排时编写或修改测试；优先让回归测试在修复前失败、修复后通过。
- 验证 Builder 的实际修改，不以 Builder 的自报结果代替独立执行。
- 先运行相关定向测试，再按现有规则运行全量 pytest、已有 lint 和本地验证。
- 检查正常路径、边界条件、错误路径、兼容性和相邻功能回归。
- 区分产品缺陷、测试环境问题和测试自身问题，不通过放宽断言掩盖失败。

Tester 默认不修改生产代码。若发现可能的修复方向，只向 Lead 提供证据和建议；需要修改生产代码时，
由 Lead 派发给 Builder。Tester 与 Builder 需要修改同一测试文件或模块时必须串行，避免并行覆盖。

## 结果回报

测试通过时，向 Lead 报告测试范围、执行命令、通过数量、跳过项以及未覆盖风险。

测试失败时必须使用以下格式，不省略字段：

```text
失败位置：
复现步骤：
预期结果：
实际结果：
可能原因：
建议修复方向：
```

“可能原因”和“建议修复方向”应与已观察证据区分；证据不足时明确标记为待验证假设。
自动验证授权继续遵守 `AGENTS.md`：应自行运行获准的非交互式生成、测试、lint 和本地验证，
不得仅因通用建议而转交给用户。
