# 日志类型提取 Bug 修复（2026-06-18）

## Bug 1: delimit 字段误判

### 根因
`classify_header_features` 无 `format_info` 参数，Step2 Path A 中 header 分类 LLM 二次判断覆盖了 Step1 确定性 `delimit=';'`，误判为 `space`。

### 修改
- `agent/tools/pipeline/log_header_processor.py`：`classify_header_features` 新增 `format_info` 参数，`analysis` 优先使用 `format_info` 的 `delimit`/`tab`
- `agent/tools/pipeline/log_classifier.py`：KV+header Path A 调用传递 `format_info={"delimit": delimit, "tab": tab}`

### Commit
`a26add6` — 修复KV格式分隔符误判

## Bug 2: KV 正则生成无重试导致流程中断

### 根因
`_generate_kv_feature_identifier` 调用 LLM 生成正则后验证失败（如 `<318>` 后无空格但 LLM 生成了 `\s+`），直接 `raise ValueError` 中断整个流程，无重试机制。

### 修改
文件：`agent/tools/pipeline/log_header_processor.py`

1. **新增 `_validate_regex` 辅助函数**：统一编译+匹配+捕获组检查，返回 `(is_valid, error_msg, body_preview)`
2. **`_generate_kv_feature_identifier` 改为循环结构**：最多 2 次尝试（初次+1次重试）
3. **重试时附加错误反馈**：将上次正则、错误原因、样例日志拼入 prompt
4. **DEBUG 级别调试日志**：每次尝试输出开始/LLM响应/解析结果/验证结果
5. **不做确定性兜底**：2 次都失败后仍 `raise ValueError`
