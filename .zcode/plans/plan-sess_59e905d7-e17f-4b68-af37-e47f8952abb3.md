# 复合意图分解 + 全量 skills 融入

## 回答你的两个问题（已确认）

1. **挂载范围**：挂载整个 `skills/` 目录（`LocalSkills("skills")`）。Agno 自动扫描所有含 SKILL.md 的子目录，一次性加载。新增 skill 只需建目录，不用改代码。
2. **一起融入**：是。`add-fields`、`delete-fields`、`merge-fields` 三个 skill 已写好但是孤岛（无任何代码挂载），既然要挂载 skills 目录，一起生效零额外成本。

调研确认：`agent/core/team.py` 当前**完全没有** skill 挂载代码；这三个 skill 的底层能力（filter 生成）在 `rule_generator` 里已存在，skill 只是 Agent 可理解的工作流包装。

## 失败链路（根因）

用户输入 `把这些枚举值做威胁映射然后填充回子规则里`：
1. detect_intent 命中"填充"→ 返回 fill → 走错路径（复合意图没被识别）
2. 枚举值（23个）存在 last_enum_extract_result，但威胁映射从不读它，全靠被截断（500字）的历史
3. RouterAgent 输出自然语言"我直接路由给ThreatAgent"而非 JSON，解析失败

## 实现方案（5 个改动点）

### 改动 1：挂载 skills 目录到 Team —— `agent/core/team.py`

```python
from agno.skills import Skills, LocalSkills

team = Team(
    ...,
    skills=Skills(loaders=[LocalSkills("skills")]),  # 挂载整个 skills 目录
)
```

挂载后 RouterAgent 自动获得 `get_skill_instructions` 等 3 个工具，通过 Progressive Discovery 按需加载。一次挂载，4+ 个 skill 同时生效（add-fields、delete-fields、merge-fields、multi-step-plan）。

**需确认**：skills 在 Team 创建时加载一次（`get_team_instance` 单例缓存），无需每次 run 重新加载。路径用项目根的绝对路径（避免工作目录依赖）。

### 改动 2：新建复合意图分解 skill —— `skills/multi-step-plan/`

标准 Agno skill 目录结构：
```
skills/multi-step-plan/
├── SKILL.md                      # 分解指令
└── references/
    └── step-types.md             # 步骤类型参考（threat/fill/enum/mapping）
```

**SKILL.md 核心指令**（纯提示词，无 Python）：
- frontmatter `description`：触发条件——"用户一句话包含 2 个及以上不同操作意图（如威胁映射+填充、枚举提取+下载+填充）时使用"
- 分解规则：识别多步意图 → 输出 `[PLAN:步骤1类型|步骤2类型|...]` 标记
- 步骤类型用现有 intent 词汇：`threat`/`fill`/`enum`/`mapping`/`log_parser`
- **保留用户原始消息全文**，系统存入 pending_steps，每步执行时传给对应执行器
- 示例：`把这些枚举值做威胁映射然后填充` → `[PLAN:threat|fill]`

**关键**：skill 只负责"理解+分解+标记"，不执行。执行由现有 handler 完成。符合 Agno skill 范式，不引入硬编码组合判断。

### 改动 3：步骤计划解析 + 自动推进器 —— `web/step_planner.py`（新建）

复用现有 `[SESSION_ACTION:xxx]` 标记机制的模式：

```python
def parse_plan_marker(result_content: str) -> list[str] | None:
    """解析 [PLAN:threat|fill] → ["threat", "fill"]"""

async def execute_pending_steps(session, team, original_text: str):
    """自动推进 pending_steps 剩余步骤。
    每步用 original_text 调用对应 handler（复用现有执行器）：
    - threat → call_team(intent=threat) + response_handler
    - fill → fill_dispatcher.handle_fill
    - enum → handle_enum_extract_flow
    """
```

**接入点**（`user_message_handlers.py`）：
- call_team 返回后检查 result_content 是否含 `[PLAN:...]`
- 有则解析存入 `session["pending_steps"]`，执行第一步
- 每步完成后（response_handler 返回 True），检查 pending_steps 是否有剩余，自动执行下一步

### 改动 4：枚举值结构化注入威胁映射 —— `input_builder.py:55-62`

threat 路径构建输入时，若 `last_enum_extract_result` 存在，注入枚举值列表：

```python
if intent == "threat":
    enum_result = user_session.get("last_enum_extract_result") or {}
    enum_values = enum_result.get("value", []) if isinstance(enum_result, dict) else []
    enum_context = ""
    if enum_values:
        enum_context = "\n\n📋 待映射的枚举值（来自上一步提取）：\n" + "\n".join(f"- {v}" for v in enum_values)
    # 拼入 prompt
```

威胁映射不再依赖被截断的历史，直接拿到结构化枚举值。

### 改动 5：放宽历史截断 —— `history_store.py:24`

`MAX_ENTRY_CHARS = 500` → `1500`，容纳枚举值列表等结构化结果。

## 预期效果

用户流程 `把这些枚举值做威胁映射然后填充`：
1. detect_intent 判 general（多意图）→ RouterAgent 处理
2. RouterAgent 触发 multi-step-plan skill → 输出 `[PLAN:threat|fill]` + 保留原文
3. 系统解析 → 存 pending_steps=[threat, fill] → 执行第一步 threat
4. threat 步骤：枚举值注入 prompt → ThreatAgent 产出映射 JSON → 存 last_threat_data
5. 自动推进 fill 步骤 → fill_dispatcher 用原文 + last_threat_data 自动填充
6. 用户无需重复输入

同时 add/delete/merge-fields 三个 skill 也生效，用户说"合并字段"等也能被 RouterAgent 处理。

## 待验证风险（实现时确认）

1. **skills 挂载路径**：Team 单例创建时用相对路径 `skills` 可能因工作目录失效，需用 `os.path.join(_project_root, "skills")` 绝对路径
2. **skill 校验**：Agno `validate_skill_directory` 会校验 SKILL.md frontmatter，需确认现有 3 个 skill 通过校验（它们已有合规 frontmatter）
3. **`[PLAN:...]` 与 `[SESSION_ACTION:xxx]` 共存**：确认两个标记的解析顺序不冲突
4. **自动推进与 chainlit context**：step_planner 自动调用 handler 时需确保 chainlit context 可用（异步链路）
